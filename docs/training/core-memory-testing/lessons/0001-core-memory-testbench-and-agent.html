第 1 课：分清哪些要“启动”

学完这一课，你能解释为什么 memory-test-a 显示 STOPPED 仍然可以测试，并能完成一次页面短期记忆闭环。

先记住一张最小地图

对象运行形态测试前要做什么
GenB 后端、Control、Runtime、Redis、PostgreSQL常驻服务启动并检查健康状态
GenB 页面浏览器中的操作入口从 http://localhost:9100/ 登录
memory-test-a/b逻辑身份 + 同一份 CLI 代码页面选择它，或用环境变量运行一次 CLI
STOPPED 不等于不能调用组件。当前 A/B 没有常驻端口、启动命令和健康检查；CLI 每次运行完会正常退出。只有以后把它开发成 HTTP 服务，才应该要求列表显示 RUNNING。

练习一：完成一次新 Session 写入

  1. 打开 http://localhost:9100/，登录后进入管理端。
  2. 点击“智能体中心”→“核心组件”→“短期记忆/工作台”→“独立测试台”。
  3. 绑定智能体选 memory-test-a。这决定记忆属于哪个智能体。
  4. Session ID 填一个从未用过的值，例如 manual-st-a-你的日期-001。新值用于证明调用前没有历史。
  5. 在“智能体服务凭证”区点击“生成服务凭证”；已有凭证但没有明文时点击“轮换服务凭证”。新凭证会自动填入测试框。
  6. 用户消息填“我偏好低风险、流动性高的理财产品。”，点击“运行真实测试”。

立即反馈：召回上下文应为 0，提交后消息应为 2。否则不要继续第二轮，先查 Session 是否真的新建、凭证是否属于 A、Control/Redis 是否健康。

练习二：证明同 Session 可以召回

  1. 智能体和 Session ID 保持完全不变。
  2. 从上方一次展示区再次复制并粘贴A凭证，因为测试输入框在上次提交后已主动清空；长期凭证本身没有失效。
  3. 输入“请读取刚才的上下文。”并再次运行。

立即反馈：召回上下文应为 2，提交后应为 4。每轮保存一条用户消息和一条测试回答。

练习三：证明 A/B 隔离

  1. 智能体改为 memory-test-b，但故意保留 A 刚才的 Session ID。
  2. 粘贴 B 的服务凭证，不能继续使用 A 的凭证。
  3. 输入“这个会话之前说过什么？”并运行。

立即反馈：召回上下文应回到 0。相同 Session 下仍为 0，才证明隔离键包含 agentId。
