# Mission: 独立完成核心记忆组件测试与验收

## Why

让项目负责人即使不了解核心组件内部代码，也能亲自操作 GenB 独立测试台和测试智能体，判断短期记忆、长期记忆、身份校验与数据隔离是否真的生效，并能把问题准确反馈给开发人员。

## Success looks like

- 能区分“必须常驻的系统服务”和“按命令运行一次的测试智能体”。
- 能逐项完成短期记忆首次写入、连续召回、Session 隔离和智能体隔离测试。
- 能逐项完成长期记忆提取、写入、召回和跨 Session 演示。
- 能获取并正确使用 A/B 服务凭证，不在页面、终端输出或文档中泄露凭证。
- 能根据页面结果、HTTP 状态和健康检查判断失败发生在哪一层。

## Constraints

- 使用本地开发环境和当前已经实现的功能，不把设计稿中的未实现能力写成可操作步骤。
- 使用中文、逐点击、逐输入的说明，并解释每个字段和每一步的原因。
- 不要求学习旧 Runtime SDK；当前核心组件通过 GenB、Control System 和 Runtime System 的 HTTP 契约协作。
- 测试数据只使用虚构信息，禁止输入真实密码、Token、验证码或 API Key。

## Out of scope

- 真实大模型回答质量评测和真实 Provider 上线门禁。
- 完整 RAG 文档摄取、切片、向量索引和引用治理。
- 将 CLI 测试智能体改造成常驻 HTTP 服务或正式生产智能体。
