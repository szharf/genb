# 五大系统与14个核心组件结构及一期功能效果确认清单

>
> 本次范围：总体结构、规划与推理引擎、短期记忆/工作台、一期效果验收
>
> 本次不讨论：代码仓库拆分、部署数量、HTTP/MCP协议、数据库和字段等具体实现

## 1. 本次评审目标

本次评审只确认四类问题：

1. 五大系统、14个核心组件和GenB核心组件模块之间的关系。
2. 规划与推理引擎应该负责什么、不负责什么。
3. 短期记忆/工作台应该保存什么、恢复到什么效果。
4. 两个组件一期演示到什么程度才算完成。

确认后再由技术团队固化Interface、数据、项目和部署方案，避免技术实现先于需求结论。

## 2. 总体结构确认

### 2.1 当前候选理解

1. 五大系统是一级能力分类。
2. 14个核心组件是五大系统下固定的14项核心能力，不是可以随意新增的组件类别。
3. 规划与推理引擎、短期记忆、长期记忆、工具注册表、策略护栏归属于Control System。
4. GenB核心组件模块统一展示和管理组件，包括目录、状态、版本、配置、智能体绑定、启停、权限和独立测试。
5. 具体组件提供实际能力；GenB不直接执行规划，也不直接充当短期记忆存储。

## 3. 规划与推理引擎确认

### 3.1 核心定位

当前存在两种需求解释：

- 运行时规划：智能体处理任务时，根据当前目标和上下文生成、调整执行计划。
- Skill生成：在智能体开发阶段，根据业务描述生成可长期复用的Skill或流程模板。

需要确认两者是否都需要，以及一期优先级。当前建议一期优先运行时规划，Skill生成后续单独讨论。

### 3.2 计划结果效果

建议规划结果可以让智能体或测试人员明确看到：

- 需要完成的步骤。
- 步骤顺序和依赖。
- 每一步需要的输入。
- 每一步建议使用的能力或工具。
- 当前缺少的材料或信息。
- 任务完成条件。
- 步骤失败后的调整建议。

### 3.4 一期效果验收候选

1. 测试人员输入一个复杂业务目标、已有材料和限制条件。
2. 组件输出清晰的步骤计划、依赖关系、缺失信息和完成条件。
3. 测试人员模拟步骤失败或材料缺失。
4. 组件输出调整后的新计划，并能区分计划版本。
5. 组件绑定测试智能体后，测试智能体能够真实获得同类规划结果。
6. 未绑定的智能体不能使用规划能力。
7. 结果不包含模型原始思维链。

待确认：上述效果是否可以作为规划与推理引擎一期验收标准。

## 4. 短期记忆/工作台确认

### 4.1 当前能力与完整工作台的差别

当前已经具备的主要效果：

- 保存当前用户的多轮对话和智能体回答。
- 返回最近会话上下文和会话摘要。
- 控制保存时间、上下文长度和数据隔离。

原始材料中的完整“工作台”还可能需要：

- 用户临时指令。
- 当前正在办理的任务和进度。
- 中间业务结果和工具结果摘要。
- 待补充材料和暂停原因。
- 下次恢复时应该继续的位置。

需要确认一期只做多轮对话记忆，还是补齐完整任务工作台。

### 4.2 跨天恢复效果

需要从用户效果上确认：

- 用户几天后回来，是只恢复原聊天，还是恢复正在办理的业务任务。
- 新开一次聊天但继续原业务时，是否仍能找到原任务进度。
- 一个任务是否允许经历多次聊天、材料补充和工具调用。
- 任务完成后是否继续保留一段时间。

### 4.4 一期效果验收候选

1. 连续多轮对话能够召回上文。
2. 可以保存临时业务指令、工具结果摘要、当前进度和待补材料。
3. 模拟暂停后重新进入，能够恢复原任务状态和继续位置。
4. 不同用户完全隔离，不同智能体默认隔离。
5. 到期内容自动失效，用户或授权管理员可以清除。
6. 密码、验证码和Token不会被保存。
7. 绑定测试智能体后可以真实调用；未绑定智能体调用失败。

待确认：上述效果是否可以作为短期记忆/工作台一期验收标准。
