# 节点管理与监控接入、升级及诊断

2026-09-15；对应节点完善计划 1.1。本文说明本轮开发产物的启用方式，是否上线须查看部署记录；不能因有操作文档就认为生产已经启用。

## 管理入口与统计口径

管理端“节点管理与监控”独立入口。管理员可登记节点、编辑说明、检查环境、切换 Python/Docker 许可、暂停新增部署、标记排空和退役。

暂停和排空不停止已有业务；禁止新的部署任务和新的入口发布/切换。已接受的部署任务继续完成，原实例必要恢复允许执行。退役要求先暂停/排空，并确认活动实例、部署、运维、检查和网关依赖清除；封存记录而非物理删除业务目录。

节点详情分“资源与告警”“项目与实例”“接入与管理”。项目按 agentId 去重、实例按 instanceId；超过90秒未更新的实例不计入确定运行数，另列待核对。资源过期保留最后值并标记，不写零。旧模式部署单列，不自动分配到某台节点；其部署记录数不是运行实例数。

## 新服务器需准备什么

| 项目 | Python-only 节点 | 允许 Docker 的节点 |
|---|---|---|
| 操作系统 | 与现有程序兼容的 Linux，具备 systemd、OpenSSH | 同左 |
| Python | 指定解释器，venv、ensurepip/pip；版本满足项目依赖 | 节点管理程序仍需 Python |
| Docker | 不安装；18 明确禁止安装 | 运维安装并验证 Docker 服务；本地策略和平台许可都允许才可使用 |
| 节点程序 | genb_node.py、node_service.py、node_metrics.py | 同左 |
| 本地策略 | 唯一 nodeId、Python 解释器、允许类型、端口池、内存/磁盘保护 | 同左，增加 Docker 许可 |
| 管理链路 | 47 上登记 SSH 别名、已核验主机指纹和专用密钥；节点固定命令授权 | 同左 |
| 业务链路 | 由实际 Nginx 代理所在服务器连接节点；直连不可行时运维登记受限隧道与端口映射 | 同左 |

节点程序目录 /usr/local/libexec/genb-node；策略 /etc/genb-node/policy.json；实例数据 /var/lib/genb-node。使用 node-runtime/install-node.sh 前，按目标节点生成 policy.json，核验绝对目录和已有文件备份。不要直接用示例策略覆盖已运行服务器的自定义策略。

控制面 trusted-targets、SSH 配置与网关 proxy-targets/端口偏移由运维维护；页面不能填任意 IP 或上传私钥。本轮仍是“运维准备＋平台登记”，不是任意服务器一键安装。

## 启用顺序

1. 保存现有数据库/程序/配置与统一入口快照，核验资源余量。
2. 执行本轮增量迁移 V20260915_02__node_management.sql、V20260915_03__node_metrics.sql、V20260915_04__deployment_diagnostics.sql；检查已有生命周期迁移已完成。本项目不自动执行 Flyway。
3. 发布兼容控制面；显式配置 runtime.node-monitoring-enabled=true 才启动采样与异步接入检查。默认关闭，避免未经准备访问节点。
4. 逐节点升级三份 Python 文件，仅给既有策略补充与平台注册一致的 nodeId；保留解释器、类型、端口和资源限制。
5. 发布中英文管理端；检查菜单、角色权限和字段。
6. 执行接入检查，核对 SSH、环境、监控协议及代理配置；NEEDS_SAMPLE 表示仍需部署隔离样例验证，不等于业务通路已经通过。
7. 通过平台选节点部署小样例，验证健康、发布确认、授权访问/拒绝、日志、停止和回收。现有真实业务不作为破坏性测试样例。

旧执行器不支持监控时显示待升级；不将未采样当零资源。不修改既有门户身份与网关撤权合同。

## 采样、历史及告警

每30秒一轮，最多2个远程调用并发，单调用5秒超时；采样使用独立线程，不占用部署或生命周期线程。CPU 使用相邻累计计数，首点/重启后为空。只读采集 /proc 和部署目录所在文件系统，不读取项目输入或秘密环境变量。

原始样本24小时、5分钟聚合7天、已恢复告警30天；清理为批量数据库操作。历史查询最多1000点，长窗口均匀取样保留首尾；采样断档不连接为连续观测曲线。

CPU/内存默认85%、部署磁盘90%，连续5分钟触发；连续2分钟正常确认恢复。节点详情可修改阈值并记录操作者及前后值。采样不可用单列 METRICS_UNAVAILABLE；不发送外部通知、不自动重启或迁移项目。

## 部署失败诊断

| 阶段 / 代码 | 检查什么 | 恢复方式 |
|---|---|---|
| NODE_PRECHECK_FAILED | 节点许可、SSH、解释器/venv、剩余资源、管理状态 | 修正环境/许可后重新检查；不通过降级权限绕过 |
| ARTIFACT_TRANSFER_FAILED | 摘要、文件大小、节点磁盘与连接 | 先确认已有材料与幂等任务结果，避免重复上传大文件 |
| REMOTE_RESULT_UNKNOWN | 请求已发送但结果未知 | 等待平台核对或查看任务；不要重复创建、释放端口或删目录 |
| REMOTE_PREPARATION_FAILED | ZIP 根目录、入口、requirements 安装日志、Python版本、编译依赖、Docker格式 | 查看实例日志；用符合目标平台的依赖材料修正后重新部署；不自动复制另一台机器的 venv |
| HEALTH_CHECK_FAILED | 监听地址、节点/容器端口、健康路径、启动时间 | 修正配置后复用材料；运行不等于健康，也不等于入口已发布 |
| 入口未生效 | 代理到节点通路、路由版本与确认、账号权限 | 在运维页面发布并等待确认；检查网关通路，不能退回裸端口绕过登录 |

复杂项目需项目负责人确认外部 LLM、Fuseki、数据库、回调和数据目录。允许提供离线轮子包等经审核材料，但本轮没有自动跨节点构建任意依赖的能力。

## 旧项目试点与回退

2026-09-15 只读清单中，Loop Engineering 与 SDD设计智能体为停止状态且各一条旧部署记录，适合优先评估；这不是已经获准迁移。运行中的 OAG 有两条记录，风险更高，须项目负责人选定后再进行。

试点前记录原部署材料、入口、身份和数据快照，先建立新实例。真实接口、刷新路径、自有登录及适用的 SSE/WebSocket 通过后才切换入口；双用户数据隔离单独验收。业务写入后不能只切流量就宣称数据已经回退。

监控异常先关闭新采样开关，不停止业务；恢复本轮前端/执行器和兼容后端。保留新表及观测历史供前向修复。旧后端不理解管理状态，若需回退旧后端，先冻结新增管理/部署入口并核对 PAUSED/DRAINING/RETIRED 节点，避免绕过新状态限制。不要删除新表或覆盖其他项目配置。
