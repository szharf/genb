# 核心组件智能体本地使用与验收手册

> 适用范围：本地开发环境；统一入口`http://localhost:9100`。
> 面向对象：第一次使用系统的产品、测试和验收人员。

## 1. 这个页面验证什么

“核心组件智能体”不是接口调试器。用户只输入自然语言，智能体在服务端完成以下步骤：

1. 携带当前用户登录态和智能体自己的长期服务凭证，向GenB申请组件会话。
2. GenB验证用户是否有权使用该智能体、凭证是否属于该智能体，以及三个组件是否已启用绑定。
3. 智能体从短期记忆读取当前`taskId`下的历史上下文。
4. Runtime System调用真实大模型生成回答或识别“创建Skill”意图。
5. 创建Skill时，规划组件先判断信息是否完整；完整后生成、校验并保存Skill草稿。
6. 智能体把本轮用户问题和最终回答写回短期记忆。

页面不会把服务凭证、Actor Token、Provider API Key或内部请求JSON交给用户。

## 2. 启动全部服务

打开PowerShell，执行：

```powershell
Set-Location D:\code\opencode\genb
.\scripts\start_customer_core_agent_local.ps1 `
  -Password '<统一登录管理员密码>' `
  -RedisPassword '<本地Redis密码>'
```

首次执行会在GenB中确保以下对象存在：

- 智能体：`core-component-demo-agent`，显示名称“核心组件智能体”。
- 绑定：`SHORT_TERM_MEMORY`、`PLANNING_REASONING`、`INFERENCE_ENGINE`。
- 推理实现：`runtime-inference-deepseek-v1`。
- 一个属于该智能体的长期服务凭证；明文只在签发时出现，随后用Windows DPAPI保存在本机`.local-secrets`目录。

启动完成后应有以下端口：

| 端口 | 服务 | 用户是否直接访问 |
|---|---|---|
| 9100 | 统一门户、GenB客户端和客户智能体代理入口 | 是 |
| 8581 | GenB后端 | 否 |
| 18704 | Runtime System真实模型推理 | 否 |
| 18705 | 短期记忆服务 | 否 |
| 18712 | 规划与推理服务 | 否 |
| 18714 | 独立客户智能体前后端 | 一般不直接访问 |

## 3. 从统一门户进入客户智能体

1. 打开Chrome。
2. 地址栏输入`http://localhost:9100/portal/login`并回车。
3. 在“账号”输入框输入管理员账号。
4. 在“密码”输入框输入对应密码。
5. 点击登录按钮。
6. 等待右侧平台卡片解锁，点击`Gen-B`卡片；这一步会把Genesis登录态兑换成GenB登录态。
7. 进入GenB后，在地址栏输入`http://localhost:9100/core-agent/`并回车。
8. 页面顶部应显示“把目标说清楚，剩下的交给我。”，右上角显示“服务在线”。

不要把`18714`作为日常入口。它证明智能体是独立服务，但不同端口属于不同浏览器Origin，不能直接共享9100的登录态；客户应始终从9100进入。

服务器部署时同样保持该结构：智能体服务独立运行，Nginx增加`/core-agent/`反向代理并去掉该前缀后转发到智能体服务。仅构建GenB前端不会自动创建这条Nginx规则。

## 4. 验收短期记忆和真实模型

1. 点击对话区的“测试短期记忆”按钮。按钮只会把示例填入输入框，不会立即发送。
2. 确认输入框内容为“我正在为A公司办理授信，请记住我偏好低风险方案。”。
3. 点击“发送”。
4. 等待按钮从“思考中”恢复为“发送”。
5. 确认智能体自然回复已记住A公司和低风险偏好。
6. 点击“查看本轮能力调用详情”。
7. 确认组件包含`SHORT_TERM_MEMORY / PLANNING_REASONING / INFERENCE_ENGINE`，模型区域显示真实Provider和模型名称；这里展示的是脱敏证据，不含凭证。
8. 不要点击“开始新任务”，直接继续输入“我刚才在为哪个公司办理什么业务，我的风险偏好是什么？”并发送。
9. 确认回答包含“A公司、授信、低风险”。展开详情后，“记忆命中”应大于0。

“开始新任务”会同时生成新的`taskId`和`sessionId`，用于验证任务隔离；点击后不应该继续召回旧任务内容。

## 5. 验收需求澄清

1. 点击“开始新任务”。
2. 输入“帮我生成一个审单Skill。”。
3. 点击“发送”。
4. 确认智能体没有直接伪造完整Skill，而是追问：输入材料、输出结果和业务约束。

这一行为由两层规则保证：大模型负责理解意图和整理自然语言；确定性代码会清除用户原文中没有明确提供的关键要求，再交给规划组件检查。

## 6. 验收完整Skill生成

1. 点击“开始新任务”。
2. 完整输入以下内容：

```text
请生成授信材料检查Skill。目标是核对企业授信申请材料是否齐全；输入为授信申请表、营业执照和财务报表；输出为缺失材料清单和检查结论；约束是不得修改原始材料，高风险结论必须人工复核。
```

3. 点击“发送”。
4. 等待生成完成；首次模型草稿格式不合格时，规划服务会自动修复一次，仍不合格则回退到确定性的安全标准模板。
5. 确认页面出现Skill卡片，包含名称、版本和完整Markdown。
6. 展开调用详情，确认规划操作为生成流程，模型仍显示真实Provider。

规划组件只生成、校验、版本化和修订Skill，不执行Skill，也不直接调用MCP工具。

## 7. 管理员检查绑定

1. 在GenB管理端打开“智能体中心 → 核心组件”。
2. 分别打开“短期记忆”“规划与推理引擎”“模型推理引擎”的详情页。
3. 在“智能体绑定”区域查找“核心组件智能体（core-component-demo-agent）”。
4. 确认三个绑定均为启用，Implementation分别指向：
   - `standalone-short-term-memory-v1`
   - `planning-reasoning-service-v1`
   - `runtime-inference-deepseek-v1`
5. 停用任意一个绑定后，客户智能体请求应返回能力不可用；恢复绑定后再次请求应成功。

## 8. 常见问题

- 页面提示没有登录状态：必须先从统一门户登录并点击Gen-B完成Token兑换，再打开客户智能体。
- 页面能打开但发送失败：检查8581、18704、18705、18712、18714是否监听，并检查三个绑定是否启用。
- Skill要求不完整却被直接生成：这是验收失败；当前实现要求关键输入、输出和约束必须来自用户原文。
- Skill首稿格式不正确：服务会自动修复一次；仍失败时使用安全模板，不会把未通过校验的草稿冒充成可用Skill。
- 为什么短期记忆存取本身不调用模型：存取、隔离、TTL和幂等是确定性能力；大模型由智能体回答和规划生成链路调用，避免模型故障破坏基础记忆。
