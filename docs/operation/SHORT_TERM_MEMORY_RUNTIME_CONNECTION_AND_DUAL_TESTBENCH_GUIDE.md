# 短期记忆运行联通与双模式测试台逐点击手册

> 版本：1.0
> 日期：2026-07-30
> 适用对象：第一次使用GenB的管理员、测试人员和智能体开发人员
> 本地管理端：`http://localhost:9100/genb/core-components/SHORT_TERM_MEMORY`
> 短期记忆服务：`http://127.0.0.1:18705`

## 1. 先理解两个测试按钮的区别

“管理员服务直测”和“智能体绑定测试”都调用真实短期记忆服务，但验证目标不同。

| 模式 | 测什么 | 是否选择智能体 | 是否需要服务凭证 | 是否检查绑定 |
|---|---|---:|---:|---:|
| 管理员服务直测 | 已注册的Implementation本身是否可用 | 否 | 否 | 否 |
| 智能体绑定测试 | 某智能体是否被允许调用该组件 | 是 | 是 | 是 |

管理员服务直测不是匿名调用。登录用户必须有`component.test`权限，GenB会校验Implementation和配置，签发5分钟内有效的管理员测试Actor Token，再调用组件服务并写审计。

智能体测试的服务凭证只证明“这是哪个智能体”。GenB还会检查：当前用户能否使用该智能体、凭证是否属于该`agentId`、绑定是否启用、Implementation是否启用、配置是否已发布。组件服务收到请求后还会再次向GenB校验凭证。

## 2. 本次已经准备好的测试对象

| 对象 | 值 | 用途 |
|---|---|---|
| 组件 | `SHORT_TERM_MEMORY` | 固定14个组件之一 |
| 契约 | `1.0.0`，已发布 | 5个业务接口和2个健康接口 |
| Implementation | `standalone-short-term-memory-v1` | 指向本地`18705`服务 |
| 调用适配 | `SHORT_TERM_MEMORY_V1` | 明确使用独立短期记忆接口，不猜URL或版本 |
| 配置 | `dual-testbench-default` v1，已发布 | 本地验收配置 |
| 专用智能体 | `standalone-memory-test-agent` | 只用于组件绑定和隔离测试 |
| 绑定 | 上述智能体→上述Implementation/配置，`ENABLED` | 智能体运行授权 |

## 3. 启动前检查

1. 打开PowerShell。
2. 执行`Get-NetTCPConnection -State Listen -LocalPort 6379,8581,9100,18705`。
3. 应看到：Redis `6379`、GenB后端`8581`、最新GenB管理端`9100`、短期记忆服务`18705`。本地不再启动`9000`备用入口。
4. 浏览器打开`http://127.0.0.1:18705/health/ready`。
5. 应看到`status=UP`和`store=REDIS`。
6. 如果`18705`没有启动，必须使用`SHORT_TERM_MEMORY_AUTH_MODE=genb`和Redis模式启动；不能用`development_headers`做绑定验收。

## 4. 从页面检查注册结果

1. 打开`http://localhost:9100/genb/core-components/SHORT_TERM_MEMORY`。
2. 使用具有核心组件权限的管理员身份进入页面。
3. 点击“接口契约”。
4. 找到版本`1.0.0`，状态应为“已发布”。
5. 点击“查看接口”，应看到：
   - `saveTaskWorkbench`
   - `getTaskWorkbench`
   - `deleteTaskWorkbench`
   - `commitShortTermTurn`
   - `prepareShortTermContext`
   - 两个健康接口
6. 关闭抽屉，点击“服务实现”。
7. 找到`standalone-short-term-memory-v1`，状态应为`REGISTERED`，调用适配应为`SHORT_TERM_MEMORY_V1`。
8. 点击“配置版本”，找到`dual-testbench-default` v1，状态应为`PUBLISHED`。
9. 点击“智能体绑定”，找到`standalone-memory-test-agent`，状态应为`ENABLED`。

## 5. 管理员服务直测：第一次写入

1. 点击详情页最后一个页签“独立测试台”。
2. 点击内层页签“管理员服务直测”。
3. 阅读蓝色提示。此页面不应出现智能体选择或服务凭证输入框。
4. 点击“服务实现”。
5. 选择`standalone-short-term-memory-v1 · SHORT_TERM_MEMORY_V1`。
6. 点击“已发布配置”。
7. 选择`dual-testbench-default · v1`。
8. “任务 ID”输入`manual-direct-task-001`。
9. “测试会话 ID”输入`manual-direct-session-001`。
10. “用户消息”输入`第一轮：请记住我正在办理企业授信任务`。
11. 点击“直接测试组件服务”。
12. 页面应提示“真实组件调用成功”。
13. 结果卡应显示：
    - 模式：`SERVICE_DIRECT`
    - 实现：`standalone-short-term-memory-v1 · 1.0.0`
    - 召回上下文消息数：首次通常为`0`
    - 提交后消息总数：`2`

如果首次不为0，表示这个`taskId`以前用过；换一个新的任务ID重测，不要删除其他人的数据。

## 6. 管理员服务直测：跨会话恢复

1. 保持“服务实现”“配置”和“任务 ID”不变。
2. 把“测试会话 ID”改为`manual-direct-session-002`。
3. 把“用户消息”改为`第二轮：请恢复上一轮授信任务`。
4. 再次点击“直接测试组件服务”。
5. 预期模式仍为`SERVICE_DIRECT`。
6. 预期召回上下文消息数至少为`2`。
7. 预期提交后消息总数至少为`4`。

这里必须改`sessionId`但保持`taskId`。这证明跨会话恢复依赖任务，而不是偷偷复用旧会话。

## 7. 智能体绑定测试：获取服务凭证

1. 点击内层页签“智能体绑定测试”。
2. 点击“绑定智能体”。
3. 搜索并选择`standalone-memory-test-agent`。
4. 页面会加载“智能体服务凭证”状态。
5. 如果显示“该智能体还没有服务凭证”，点击“生成服务凭证”。
6. 如果已有有效凭证但你没有明文，点击“轮换服务凭证”。
7. 阅读警告：轮换后旧凭证立即失效。
8. 点击确认按钮。
9. 页面黄色提示中只展示一次新凭证，并自动填入下方密码框。
10. 如真实智能体需要使用，点击“复制”并保存到智能体自己的Secret/环境变量中；不要写入普通配置、文档、截图或Git。

页面刷新后不能重新获取原凭证明文，这是安全设计，不是页面故障。

## 8. 智能体绑定测试：写入和恢复

第一次：

1. “任务 ID”输入`manual-agent-task-001`。
2. “测试会话 ID”输入`manual-agent-session-001`。
3. 确认服务凭证输入框已有自动填入的值。
4. “用户消息”输入`第一轮：保存智能体正在处理的任务`。
5. 点击“运行真实测试”。
6. 结果模式应为`AGENT_BINDING`，首次上下文通常为0，消息总数为2。

恢复：

1. 保持任务ID不变。
2. 会话ID改为`manual-agent-session-002`。
3. 消息改为`第二轮：恢复智能体上一轮任务`。
4. 再次点击“运行真实测试”。
5. 上下文消息数应至少为2，消息总数应至少为4。

## 9. 绑定控制负向测试

此测试用于证明服务凭证不能绕过绑定。只操作专用测试智能体。

1. 先确保已经获得当前有效凭证明文；停用绑定不会自动清空页面输入框。
2. 打开“智能体绑定”页签。
3. 找到`standalone-memory-test-agent`。
4. 点击“停用”，确认状态为`DISABLED`。
5. 回到“独立测试台”→“智能体绑定测试”。
6. 使用原凭证点击“运行真实测试”，预期失败，提示没有生效绑定。
7. 切到“管理员服务直测”，用同一个Implementation和配置测试，预期仍成功。
8. 返回“智能体绑定”，点击“启用”，确认恢复为`ENABLED`。

不要在绑定停用状态结束验收。

## 10. 如何判断安全校验是否生效

| 操作 | 预期 |
|---|---|
| 直接向`18705`传`X-Tenant-Id/X-Agent-Id/X-User-Id`，不传Actor Token | HTTP 401 |
| 智能体凭证错误 | 调用失败 |
| 凭证属于A、请求`agentId`填写B | 调用失败 |
| 绑定停用 | 智能体测试失败 |
| 绑定停用时管理员服务直测 | 成功 |
| Implementation停用或配置未发布 | 服务直测失败 |

短期记忆服务正式模式只信任GenB签名Token中的tenant/user/agent；页面不能自己决定隔离身份。

## 11. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面“核心组件详情加载失败” | `9000`的Vite代理未连上`8581` | 重启管理端并设`VITE_PROXY_TARGET=http://127.0.0.1:8581` |
| 服务实现下拉为空 | 没有`REGISTERED`实现 | 先在“服务实现”注册并启用 |
| 配置下拉为空 | 所选实现没有已发布配置 | 创建配置草稿并发布 |
| 智能体下拉没有目标 | 绑定未创建或未启用 | 在“智能体绑定”创建/启用 |
| 服务凭证框为空 | 页面刷新后明文不恢复 | 轮换凭证并立即安全保存 |
| `18705/health/ready`返回503 | Redis不可达或密码/DB配置错误 | 检查Redis连接；服务不会静默降级 |
| 自报Header返回401 | 正式`genb`鉴权正在工作 | 应由GenB测试台或智能体链路调用 |
