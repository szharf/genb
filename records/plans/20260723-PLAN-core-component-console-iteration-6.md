# 核心组件平台 Iteration 6 计划：管理端目录页与无物理外键数据库门禁

## 一、目标

本轮把已完成的 GenB 核心组件控制面从“只有 API”推进到“管理员可见、可查、可理解”的第一版页面，同时修正 Hibernate 自动建表产生物理外键的问题。

交付结果不是静态设计稿：页面必须读取远程开发后端提供的固定五系统/14组件目录，不使用前端假数据；接口失败时明确报错并允许重试。

## 二、数据库决策

领域模型继续保留以下逻辑关系：系统包含组件、组件包含实现、实现包含配置版本、智能体绑定实现和配置。设计文档可把这些关系画成外键。

实际数据库执行以下规则：

1. 表只创建主键、唯一约束、非空约束、检查约束和查询所需索引。
2. 不创建 `FOREIGN KEY`，包括 Hibernate、测试库和手写 SQL。
3. 写入关联数据前由服务层查询并校验被关联记录存在。
4. 同一事务完成关联校验和写入；并发唯一性依赖唯一索引兜底。
5. 删除采用状态机或软删除；需要物理删除时按依赖顺序由应用服务显式执行。
6. 远程库已有物理外键通过独立兼容迁移删除，迁移不得删除业务行。

## 三、页面组件边界

| 模块 | 单一职责 | 输入/输出 |
|---|---|---|
| `views/core-components/Index.vue` | 路由级组合页面 | 组合目录容器 |
| `CoreComponentCatalog.vue` | 编排筛选、分组和页面状态 | 无 props；调用 composable |
| `CoreComponentFilters.vue` | 展示筛选条件 | props 下传，emit 查询/重置/刷新 |
| `CoreComponentCard.vue` | 展示单个固定组件 | `component` prop，emit `select` |
| `useCoreComponentCatalog.js` | 请求、筛选、分组、错误状态 | 返回只读状态和显式 actions |
| `api/coreComponent.js` | 核心组件 HTTP 契约 | `list()` |

## 四、开发步骤与验收

### WP1 数据库门禁

- 写 H2 metadata 测试，断言七张控制面表不存在 imported foreign key。
- 在 JPA 逻辑关联上明确配置 `ConstraintMode.NO_CONSTRAINT`。
- 提供远程 PostgreSQL 兼容脚本，仅删除这七张表上的物理外键。
- 提供迁移前后表行数和约束验证查询。

验收：测试生成 DDL 无外键；迁移脚本无 `DELETE`、`TRUNCATE`、`DROP TABLE`。

### WP2 目录页面

- 增加菜单和路由。
- 增加目录 API 和 composable。
- 按系统分组展示组件卡片。
- 支持关键字、系统、状态筛选、重置和刷新。
- 支持加载、空结果、权限不足和网络错误状态。

验收：真实 API 返回 5 个系统和 14 个组件时完整展示；前端不允许新增固定组件。

### WP3 国际化和构建

- 中文构建使用 `systemNameZh/componentNameZh`。
- 英文构建使用 `systemNameEn/componentNameEn`。
- 固定页面文案全部进入 Vue i18n。

验收：`npm run build:zh`、`npm run build:en` 均成功。

### WP4 回归和交付

- 运行前端逻辑测试和双语构建。
- 运行后端专项测试及全量测试。
- 检查源码中敏感信息和物理外键声明。
- 更新任务、报告、索引并精确提交。

## 五、本轮不包含

- 不开发短期记忆、长期记忆数据面。
- 不做实现注册、配置发布、智能体绑定和服务凭证的前端表单。
- 不部署生产环境。
- 不删除远程数据库中的任何业务数据。
