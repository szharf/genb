# GenB 单体容量例外生产部署任务计划

- 日期：2026-08-18
- 状态：M0已执行，Gate A未通过；等待容量恢复与客户端发布范围确认
- 负责人：GenB 平台与服务器运维协作
- 范围：仅部署 GenB 后端、GenB 管理端/客户端中英文静态产物，以及 GenB 必需的数据库增量迁移；按需精确调整 GenB 既有 Nginx 路由
依赖：已完成的本地实现 Gate F、2026-08-13 GenB 白名单治理记录、维护窗口、部署授权与容量例外授权

## 背景与本次决策

用户决定暂时只部署 GenB，核心组件服务和智能体不部署。原《GenB 统一数据面网关生产部署任务计划》继续保留，但本轮不执行其中的网关、专用 Redis、核心组件、智能体和 `/agents/` 切流步骤。

后端根分区当前约 94%，仅余约 6.2 GiB，未满足既有“低于 80% 且至少 20 GiB 可用”的 Gate B。由于容量治理在此阶段停止，本计划不是宣告原 Gate B 通过，而是为体量较小的 GenB 单体发布定义一次受控的容量例外。任何硬停止条件触发时，仍必须停止部署。

## 部署边界

### 本轮部署

- GenB 后端 `gen-b-console-1.0.0.jar`，仍使用现有 8581 运行方式。
- GenB 管理端中文/英文静态产物，对应现有 `/genb/`、`/genb-en/`。
- GenB 客户端中文/英文静态产物，对应现有 `/genb-client/`、`/genb-client-en/`。
- GenB 必需的 PostgreSQL 增量迁移；迁移必须显式执行、可审计且通过回滚兼容验证。
- 仅当现有 GenB 路由不能承载新静态产物时，精确修改共享 Nginx 配置中的 GenB location；否则 Nginx 配置不变。

### 本轮明确不部署或不修改

- 不部署统一数据面网关、专用 Redis、Runtime、短期记忆、长期记忆、规划与推理或其他核心组件服务。
- 不部署 18714 或任何其他智能体，不新增 `/agents/`、`/component-api/` 路由，不开放任何智能体裸端口。
- 不创建 `/app/genb-data-plane/`、Docker 网络、容器、镜像或卷。
- 不发布组件配置，不修改组件绑定，不生成或轮换智能体/组件服务凭证，不启用 Agent SSO 生产入口。
- 不修改或清理 GitLab、GenC、GenO、Journey、其他项目、现有 Docker、现有 Redis及其数据。
- 不执行任何 Docker `prune`，不修改 Docker daemon 全局日志配置。
- 不在服务器编译 Maven/Node 项目，不上传源码、`node_modules`、Maven 缓存或本地 `target` 中的散文件。
- 不提交、暂存、推送或覆盖当前本地脏工作树；发布快照和产物来源必须单独留证。

## 当前事实与失败基线

- 本地统一数据面相关实现已通过 Gate F；但本轮只发布其中的 GenB 控制面代码和前端，不发布数据面运行单元。
- 2026-08-13 已删除 23 个精确归属的 GenB 旧 JAR并安装 GenB 专用 logrotate；当时保留当前 JAR与两个回滚 JAR。
- 2026-08-17 只读复核显示后端根分区约 94%、可用约 6.2 GiB；四天较 2026-08-13 减少约 2.5 GiB。
- 空间下降的主要来源为其他项目 GitLab 容器的 Docker JSON 日志；本计划只把它作为整机风险，不修改或清理该资产。
- 后端可用内存约 4.9 GiB、无 Swap；现有 GenB 继续运行且健康。
- 本地工作树包含大量未提交的 GenB 变更。未冻结发布快照、未生成最终产物哈希前，不具备可追溯发布条件。
- 新增 SQL `V20260812_01`、`V20260812_02` 尚未在生产执行；其中非空列变更可能影响旧 JAR 回滚后的写入，必须先做向后兼容验证。
- 当前 `application.yml` 使用 `spring.jpa.hibernate.ddl-auto: update`；生产发布不得依赖 Hibernate 自动猜测和执行本轮结构变更。

## 成功标准

- 只替换 GenB 白名单资产，其他项目运行态、文件、容器、网络和数据零修改。
- 后端、四套静态产物、数据库迁移均有发布前哈希、精确备份、验证和回滚点。
- 部署峰值期间后端根分区始终低于 95%，可用空间始终不少于 5 GiB；预计峰值新增占用不超过 1 GiB。
- 后端可用内存始终不少于 3 GiB；GenB 重启后健康在 120 秒内恢复。
- 管理员和普通用户的统一登录、退出、权限、管理端、客户端和中英文入口通过真实浏览器验收。
- 未出现 `/agents/`、核心组件或智能体新入口；未部署的数据面功能不会被误标为生产可用。
- 发布后至少观察 24 小时，5xx 无持续增长，GenB 日志轮转正常，磁盘不触发硬停止线。

## 产物与容量预算

执行前必须形成产物清单，至少包括 JAR、四个压缩后的静态产物、两份 SQL、必要配置及其 SHA-256。服务器只接收已在本地完成测试和构建的产物。

容量按最坏峰值计算：

`峰值新增 = 上传包 + 解压/新 JAR + 当前版本备份 + 数据库临时文件/日志增长 + 24 小时磁盘增长预留`

Gate 使用以下硬规则：

- 开始上传前若根分区使用率达到或超过 95%，或可用空间少于 5 GiB，停止。
- 峰值新增预算超过 1 GiB，或计算后预计可用空间少于 5 GiB，停止。
- 每上传、解压、备份一个阶段都重新检查空间；不能用“文件很小”替代实测。
- 数据库备份不得落在后端根分区；应流式保存到已批准的外部备份位置或本机 D/E 盘受控目录，并记录哈希、权限和恢复验证。
- 产物启用并校验后，服务器上传暂存包按精确路径删除；回滚 JAR和当前静态版本仍按计划保留。

这些阈值只是本次小体量发布的最低保护线，不代表服务器容量问题已经解决。

## 数据库策略

- 在生产数据副本上先执行两份增量 SQL，验证现有数据回填、约束、重复执行和新 JAR启动。
- 在同一副本上再启动旧生产 JAR，验证登录、读取以及旧版本仍可能执行的实现注册/更新写入。
- 若旧 JAR 在新结构上写入失败，Gate B 不通过；先将迁移改造成向后兼容版本并重新完成全套验证。
- 生产执行前对目标 schema 做外部备份；记录 schema、受影响表行数、DDL和约束快照。
- 生产迁移应显式执行，并通过环境覆盖将 `SPRING_JPA_HIBERNATE_DDL_AUTO` 设为 `none` 或经验证的等效值，禁止让 Hibernate 在启动时继续自动改表。
- 迁移以新增和回填为主，不在本轮删除表、列或业务数据。回滚应用时默认保留新增结构，禁止现场直接 `DROP`；如需数据修复，另立脚本和授权。

## 执行步骤与 Gate

### M0：范围冻结与只读复核

1. 冻结明确的发布源快照，记录当前 Git 提交、未提交变更清单和发布内容；不得把无关脏工作树变更混入产物。
2. 在本地重新运行 GenB 后端专项/全量测试、管理端/客户端测试与四套生产构建。
3. 生成产物 BOM、SHA-256、压缩大小、解压大小和峰值容量预算。
4. 只读复核两台服务器的磁盘、inode、内存、GenB PID/健康、8581、四个静态目录、Nginx GenB 路由和数据库迁移状态。
5. 记录维护窗口、预计 GenB 后端中断时间、验收人员、通知范围和精确回滚命令。

Gate A：范围完全等于“仅 GenB”；测试/构建全绿；产物可追溯；容量和内存不触发停止线；现有 GenB 与入口健康。否则不上传。

### M1：数据库兼容与发布演练

1. 在生产数据副本上演练增量 SQL，验证重复执行、数据回填、约束和耗时。
2. 依次验证新 JAR和旧生产 JAR对迁移后数据库的读写兼容。
3. 使用与生产等价的外部配置启动新 JAR，确认未部署核心组件和智能体时，GenB基础功能仍可用。
4. 演练 JAR、静态目录和 Nginx（如需修改）的精确回滚；数据库只做向前兼容，不以破坏性降级作为回滚手段。

Gate B：迁移与旧 JAR兼容验证全部通过；生产备份与恢复命令可用；未部署服务不会导致 GenB 启动或健康失败。

### M2：受控上传与生产备份

1. 再次检查磁盘和内存，按 BOM逐项上传预构建产物到 GenB 专用暂存目录，每项校验 SHA-256。
2. 将数据库备份直接写往批准的外部位置，不在服务器根分区保留完整备份。
3. 精确备份当前运行 JAR、四个静态目录和将修改的 Nginx 文件；先核对当前真实路径和哈希。
4. 若新增当前 JAR备份会使保留数超过“当前＋两个回滚版本”，只记录待归一化清单；部署完成前不删除现有回滚点。

Gate C：备份可读、哈希一致、空间仍不少于 5 GiB、未接触范围外资产，才进入切换。

### M3：GenB 后端发布

1. 进入维护窗口，记录最后健康状态和数据库受影响表快照。
2. 显式执行已演练的增量 SQL并校验结构、约束、回填行数。
3. 使用现有精确启停方式停止 GenB，原子替换 JAR，加载生产外部配置并启动；不改变其他进程。
4. 在 120 秒内验证进程、8581、`/api/actuator/health`、数据库连接、现有 Redis连接和错误日志。
5. 若启动、健康或基础接口失败，立即恢复旧 JAR；新增数据库结构保留并按已验证的兼容路径运行。

Gate D：GenB 健康稳定，登录和核心管理读取接口通过，磁盘/内存符合阈值，日志无持续异常。

### M4：四套静态产物与必要路由发布

1. 在前端服务器的 GenB 白名单目录旁解压新产物，校验入口文件和静态资源完整性。
2. 使用同文件系统目录重命名完成原子切换，保留部署前版本作为回滚点。
3. 默认不修改 Nginx；确需修改时只改 GenB location，先备份、执行 `nginx -t`，通过后仅 reload。
4. 不增加 `/agents/`、`/component-api/` 或任何核心组件路由。

Gate E：四个入口均返回 200、资源无 404、API代理正常，Nginx 全量配置测试通过，现有门户及 GenC/GenO公开入口只做外部健康回归。

### M5：真实用户验收与观察

1. 使用管理员与普通用户完成统一登录、权限差异、退出、刷新和重新登录。
2. 验收中文/英文管理端与客户端；确认未授权用户不能进入管理功能。
3. 验证智能体访问不会被误宣告为已上线；不测试或启用未部署的核心组件调用。
4. 连续观察 30 分钟后结束维护窗口，并继续保留 24 小时观察：GenB健康、5xx、内存、磁盘、日志增长和 logrotate。
5. 删除已校验且不再需要的精确暂存包；将 JAR和静态回滚版本归一到约定保留数。
6. 写部署记录、验收报告并更新任务看板和索引。

最终 Gate：所有 GenB 必须项通过，范围外资产零修改，24 小时观察无阻塞异常后，才将本次“仅 GenB 部署”标记完成。核心组件和智能体仍明确为未部署。

| 产物 | JAR、四套静态产物、SQL、配置哈希 | 与本地验收产物逐项一致 |
| 数据库 | 重复迁移、新旧 JAR兼容、备份恢复 | 无破坏性变更，旧 JAR回滚路径可运行/写入 |
| 后端 | 健康、登录、权限、管理读取/写入 | 120 秒内 UP，无持续 5xx/异常日志 |

| 范围 | 核心组件、智能体、其他项目资产 | 无新增进程/容器/路由，无文件或数据修改 |

## 回滚顺序

1. 停止继续验收和流量扩大，记录故障时间、请求和日志证据。
2. 如修改过 Nginx，恢复精确备份并在 `nginx -t` 通过后 reload。
3. 将四个 GenB 静态目录原子恢复为部署前版本。
4. 停止新 GenB，恢复部署前 JAR和外部配置，启动并验证健康与统一登录。
5. 数据库新增结构默认保留；只有经单独批准和恢复验证后才能做数据修复，不现场删除新列/表。
6. 验证 GenB、门户及其他现有项目公开入口恢复；写清回滚结果。

## 风险与硬停止条件

- 根分区达到 95%、可用空间少于 5 GiB、inode异常或空间快速下降：立即停止；不进入其他项目清理。
- 可用内存少于 3 GiB、GenB RSS持续异常增长或系统出现 OOM信号：立即回滚。
- 生产备份无法在外部位置完成或无法校验：不得迁移数据库。
- 新迁移破坏旧 JAR兼容：不得进入生产发布。
- 最终产物无法对应明确源快照，或混入范围外代码：不得上传。
- 任何需要部署网关、组件、智能体、新 Redis或 Docker资产的行为都属于扩展范围，必须暂停并另行批准。
- GitLab日志仍可能继续消耗根分区；24 小时观察通过也不解除后续容量风险，只证明本次 GenB 发布未直接造成异常。
