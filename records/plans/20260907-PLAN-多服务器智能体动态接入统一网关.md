## 1. 项目经理阅读摘要

目标是让管理员在 GenB 登记服务器和智能体运行实例，检查并发布后，用户从固定入口访问。符合接入规范的新智能体加入已有节点时，不修改网关源代码、不增加专属 Nginx location、不重启网关程序。

“修改程序”与“发布配置”分开：网关始终执行同一套鉴权和转发流程；GenB 发布版本化的路由通讯录，告诉网关智能体位于哪里、允许怎样访问。

一期交付：多节点运行位置登记、上传时选择节点、部署材料远程分发、远程导入和启停、状态与日志查询、普通智能体独立路由、动态端点授权、配置发布及生效反馈、客户端按发布状态访问、双节点试点验收。

一期不承诺：自动扩容、同一智能体多副本负载均衡、故障自动迁移、正在生成的回答无缝恢复。远程部署执行器已纳入本计划；首版远程自动部署采用 Docker 镜像归档，其他部署类型保持原有行为或经检查登记接入，不默认获得远程执行能力。

核心验收演示：原智能体继续使用；管理员上传 Docker 镜像归档并选择第二节点，平台完成分发、导入、启动和健康检查；管理员发布；获授权用户通过固定入口使用，未授权用户被拒绝；网关进程未重启；在管理端查看远程日志并完成受控停止、再启动；再迁移该试点的目标地址，用户入口保持不变。

用户流程：上传智能体并选择运行节点 → 查看上传/分发/启动进度 → 健康检查通过 → 发布 → 访问 https://实际域名/agents/{agentId}/。部署成功不自动代表已发布。

节点边界：47 可作为拟纳管的运行节点，实施前核验。18 当前为统一前端与 Nginx 服务器，不默认显示为可部署节点；只有另行调整职责并通过资源、隔离和授权检查后才可纳入。测试优先选择 47 对应的隔离环境与新增运行节点，不据本计划操作生产机器。

## 3. 假设、范围与决策

### 3.1 假设和待确定事项

- 首批智能体采用可由现有代理承载的 HTTP、SSE 或 WebSocket；每个智能体一期只有一个接收新流量的主实例。
- 测试至少有两个真实隔离节点；同机两个端口只可作为本地测试，不能证明跨主机连通。
- 运维提供网关到节点的业务连通；管理网络连通不能代替业务网络连通。
- 试点是否包含本机文件、SQLite、内存会话，须在 M0 确认；有状态迁移缺少数据方案时不进行迁移验收。
- 网关部署位置、测试节点、试点应用、预计并发和入口域名待评审；不据此虚构工期或线上容量。
- 假设被推翻时更新范围、合同和 Gate，再继续相关实现。

### 3.2 方案选择

采用现有 Nginx 字节流代理加轻量网关鉴权、GenB 发布配置的结构，延续 20260812 ADR，不恢复已撤下的生产核心组件菜单。

| 候选方案 | 结论与理由 |
|---|---|
| 每新增智能体手写 Nginx | 不采用；人工变更多，难以提供管理端发布状态 |
| 每个智能体生成专属网关代码 | 不采用；上线成本随智能体数量增长 |
| GenB 动态发布路由与受控端点 | 采用；复用现有网关，业务新增主要表现为配置变化 |
| 新增完整容器集群调度系统 | 本期不引入；当前目标是接入和发布，不扩大到调度平台建设 |
| 受控 SSH 节点执行接口 | 首版采用；集中实现分发、导入、启停、状态和日志，禁止各 Controller 自行拼接远程命令 |
| 常驻节点执行器主动领取任务 | 保留后续扩展；若实际网络不支持首版管理连接，M0 更新决策和成本，不并行实现两套生产方案 |

M0 补充中文 ADR，记录独立路由、动态端点授权及入口/目标分离；新 ADR 为现有决策的扩展，不静默替代身份、安全和核心能力合同。代价是新增发布状态、节点资产和配置版本兼容管理。

### 3.3 现状到目标

| 对象 | 当前 | 目标 | 兼容策略 |
|---|---|---|---|
| 普通智能体路由 | 从组件绑定间接产生 | 独立检查和发布 | 组件绑定只决定能力调用 |
| 目标端点 | 启动环境精确列表 | 获准节点实例生成动态端点清单 | 保留独立网络约束，不允许任意 URL |
| 地址 | accessUrl 同时承担访问与上游含义 | launchUrl 对外、upstreamOrigin 内部 | 原字段保留至分类迁移结束 |
| 发布结果 | 有配置版本基础 | 区分保存、发布、网关应用和可访问 | 未应用不显示接入完成 |
| 运行位置 | 智能体字段与容器记录 | 节点—实例—智能体关系 | 一期单主实例，数据结构容纳未来多实例 |
| 部署与运行操作 | 已发现多处后端 ProcessBuilder 调用，完整调用链待 M0 盘点 | 所有纳管 Docker 操作显式绑定 nodeId 和 instanceId | 本地节点也走统一接口，未迁移类型保持原行为 |

## 4. 模块与信任边界

| 模块 | 职责和接口 | 生产依赖 / 测试替身 |
|---|---|---|
| GenB 节点与实例管理 | 登记节点、关联智能体实例、校验端点归属 | 数据库仓储 / 隔离测试数据库 |
| 部署任务与材料管理 | 上传校验、版本材料、任务状态机、资源预检和恢复 | 持久化任务与受控文件存储 / 测试数据库和临时材料库 |
| 节点执行接口 | transfer、import、start、stop、inspect、logs；只执行受控动作 | SSH/SFTP 与节点受限执行入口 / 可注入超时和部分成功的测试执行器 |
| GenB 路由发布服务 | 检查、发布、撤下、生成不可变配置版本 | 现有版本和事件机制 / 可控事件接收器 |
| 网关配置模块 | 拉取、完整校验、原子应用、确认版本 | 控制面 HTTP、Redis / 内存配置源和存储 |
| 网关访问模块 | 会话授权、已发布目标选择、可信身份 | 现有签名与会话实现 / 双用户身份夹具 |
| Nginx | 通用路径和字节流代理 | 真实隔离 Nginx / 协议测试上游 |
| 管理端与客户端 | 显示部署位置、发布进度、有效入口 | 后端 API / 合同响应夹具 |

浏览器是不可信来源，不接受其自报用户 ID、租户 ID、内部目标或代理身份 Header。Nginx 删除并重建可信 Header。GenB 与网关内部接口使用机器身份；节点登记、路由发布、用户访问分别校验权限。

配置快照不包含密码、Token、私钥或完整环境文件，仅保存必要的凭据引用。浏览器只获得对外入口，不接收内部路由表。上游只获得必要身份，不能把访问入口鉴权当作业务数据隔离证明。

## 5. 接口、数据与状态设计草案

本节命名为拟议合同，M0 核对既有接口后冻结，不代表已经实现。

### 5.1 数据实体

- 节点：nodeId、环境、管理状态、获准业务地址；IP 不作主键。节点授权和路由发布不能由普通用户越权执行。
- 实例：instanceId、agentId、nodeId、版本、协议、业务端口、健康结果和观测时间。端口占用按节点与绑定地址校验。
- 路由草稿：agentId、instanceId、入口模式、身份模式、检查结果；业务分类和权限仍归原智能体。
- 路由发布：revision、完整配置、摘要、创建人、创建时间、发布结果。发布后版本内容不可修改，回退发布新的递增版本。
- 网关确认：gatewayId、进程启动标识、appliedRevision、摘要、确认时间、错误码；配置版本一致不等于上游健康。
- 原有 AgentDeployment 的部署材料语义先核对，再选择外键扩展或关联新实例，不直接按文件名推断运行副本。
- 部署材料：artifactId、大小、SHA256、类型、版本、受控存储引用、上传者、校验状态；名称仅作展示，同名不同内容不得覆盖已引用版本。
- 部署任务：jobId、agentId、artifactId、nodeId、instanceId、幂等键、请求摘要、阶段、进度、租约/执行代次、超时、结果和审计。幂等键在操作者与操作范围内唯一，同键不同参数返回冲突。
- 节点补充角色、是否允许部署、执行连接/凭据引用、CPU 架构、Docker 能力、资源观测时间。管理地址与业务地址分别保存。
- 节点/实例被已发布路由引用时禁止直接删除；先撤下或切换。审计保留操作者、对象、前后版本和结果，保留期 M0 明确。

### 5.2 拟议接口与状态

| 接口族 | 请求与响应要点 | 权限 / 错误 |
|---|---|---|
| /api/v1/runtime-nodes、/runtime-instances 的登记与查询 | 节点、实例、分页和观测状态 | 节点管理权限；400、403、409 |
| 既有 /api/v1/deploy/upload 的兼容扩展 | 上传归档，返回 artifactId、校验状态；nodeId 选择与后续任务关联 | 上传权限；大小超限 413、校验失败 422；M0 核对旧响应兼容 |
| POST /api/v1/deployment-jobs | agentId、artifactId、nodeId、版本化运行参数、幂等键；返回 202 和 jobId | 该智能体及目标节点部署权限；409 冲突、422 预检失败 |
| GET /api/v1/deployment-jobs/{id} | 各阶段进度、目标节点、结果和可恢复操作 | 任务可见性授权，错误不泄露凭据 |
| POST /api/v1/runtime-instances/{id}/actions | start、stop、cancel 等受控操作及 expectedVersion；返回异步任务 | 实例操作权限；禁止客户端指定任意命令或容器 ID |
| GET /api/v1/runtime-instances/{id}/logs | 有界行数、字节上限及游标；返回脱敏日志 | 实例日志权限；明确超时、轮询限流，不无限读取 |
| POST /api/v1/agents/{id}/route/check | instanceId、草稿版本；返回检查编号及分项结果 | 发布权限；无效端点拒绝，不接受任意探测 URL |
| POST /api/v1/agents/{id}/route/publish | 草稿版本、expectedRevision、幂等键；返回 202 和发布编号 | 发布权限；并发冲突 409、前置未通过 422 |
| GET /api/v1/route-publications/{id} | 配置版本、网关确认、探针结果和失败原因 | 获准管理员 |
| POST /api/v1/agents/{id}/route/withdraw | expectedRevision、幂等键；返回发布编号 | 发布权限；重复请求返回同一逻辑结果 |
| 既有内部 config/version、config/snapshot | 扩展独立路由、受控端点及新 Schema 版本 | 机器身份；版本或结构不兼容拒绝 |
| 拟增内部 config/ack | gatewayId、版本、摘要、应用结果 | 机器身份绑定实例，拒绝伪造确认 |
| 客户端智能体响应 | launchMode、launchUrl、accessState、不可访问原因 | 用户可见对象授权；不返回内部目标 |

状态分别保存：草稿检查通过、发布处理中、配置已应用、入口可访问、失败、已撤下；节点失联记为未知，不假称实例已停止。客户端不得仅凭端口或容器运行数认定网关入口可访问。

检查及发布采用异步任务，M0 固定连接超时、总超时、请求大小和错误结构；不在单个 HTTP 请求中无限等待。页面及文件流量沿用真实应用需要的限额，测试大请求、SSE、WebSocket 和背压。普通业务写请求不得因切换而自动重放。

## 6. 关键运行过程

### 6.1 新智能体发布

1. 管理员选择已登记实例，系统验证目标属于获准节点且接入检查通过。
2. 事务校验 expectedRevision，保存完整不可变发布版本；通知在事务提交后发送。
3. 网关收到通知或版本轮询发现变化，拉取同一版本的端点清单与路由。
4. 校验节点授权、Schema、摘要和路由引用关系后整体应用；失败不得部分放行。
5. 网关确认版本；GenB 对本次目标网关集合核对确认并检查入口，才显示生效。
6. 两个用户分别验证授权与拒绝；原智能体回归。新发布不要求绑定核心组件。

### 6.2 节点切换、撤下及权限撤销

1. 新节点实例完成验证，发布新版本切换目标，新请求使用新目标。
2. 旧请求按限定排空策略处理；不承诺现有流式连接迁移到新实例。
3. 下线停止新访问；安全撤权与普通排空不同，现有长连接的终止/重新鉴权策略须在 M0 固定并测试，不能只验证新连接。
4. 回退生成更高版本，重新指向仍健康的旧实例，重新检查用户入口。

### 6.3 配置或网络故障

- 通知丢失由版本检查兜底；确认丢失可幂等重报，不创建重复发布。
- 新快照非法则拒绝应用，显示失败，不能把旧路由仍可用误报为新发布成功。
- 控制面不可用沿用现有高风险有效期和低风险宽限边界；不延长授权过期来维持表面可用。
- 节点故障时返回明确不可用；本期不自动迁移。Redis 故障、进程重启、配置回退纳入注入测试。
- 多网关只完成部分确认时显示部分生效，不宣布全量完成；服务流量中的滞后实例必须受隔离策略约束。

### 6.4 上传、远程部署与恢复

1. 管理员上传归档并选择有权限的运行节点；节点不在线、不允许部署或观测过期时不允许直接执行。前端分别显示上传、分发、导入、启动、健康检查进度。
2. 服务端流式落盘并计算 SHA256，使用服务端生成的存储路径；校验大小、材料类型和可用空间，材料校验通过才允许创建部署任务。
3. 创建持久化任务并预留节点资源与端口；容量估算包括上传文件、远端临时副本、导入镜像层和容器可写层。镜像展开大小未知时采用 M0 固定的保守预算及导入监控，不能只凭归档大小放行。
4. 通过受控 SFTP 等机制传到目标节点任务目录；使用临时文件，远端校验完成后原子标记可用。失败时保留有界诊断信息，不导入不完整文件。
5. 在目标节点导入镜像，校验架构和材料对应的镜像标识；使用结构化参数启动容器，并写入 agentId、instanceId、jobId 和执行代次等归属标签。
6. inspect 确认容器状态，执行应用健康检查；成功后登记真实实例和内部目标。容器运行不等于健康，健康失败不得发布路由。
7. 部署任务状态至少包含 QUEUED、PREFLIGHT、TRANSFERRING、IMPORTING、STARTING、VERIFYING、SUCCEEDED、FAILED、CANCEL_REQUESTED、CANCELED、UNKNOWN。UNKNOWN 表示失联或结果不确定，不能直接重试创建。
8. 后端重启或连接超时后，先按节点、实例标签和 jobId 对账。任务租约与执行代次阻止旧执行者迟到写入；远端幂等锁/标识防止租约重领产生重复副作用。
9. 取消为尽力而为的请求；已启动的实例按确认后的补偿步骤处理。只清理本任务拥有的临时文件和容器，不删除共享镜像、业务卷或他人资源；凭据和完整环境不进入任务日志。
10. 任务成功后由独立发布流程开放固定入口。更新已有智能体时旧实例继续服务，直到新实例健康并切流；新部署失败不停止原服务。

### 6.5 远程启停与日志

- 所有操作通过 instanceId 查出 nodeId 和经过验证的容器归属，禁止在请求失败时回落到控制面本机执行。日志、镜像导入状态、运行数量、监控和删除链路均纳入调用链盘点。
- 停止已发布实例时先撤下或切换路由并确认，再按排空策略停止目标；路由撤下不能确认则普通停止流程停在前置阶段，不偷偷停服务。
- 再启动需重新检查健康；不自动恢复已撤销的使用权限或发布状态。两节点同端口实例必须能独立启停、查询状态和日志。
- 首版不保证大文件断点续传，失败支持明确重传，幂等任务防止重复导入/启动。若要续传需另加协议、校验和验收，不能把现有上传修复当作已支持续传。

## 7. 安全、兼容和质量要求

- SSH 校验固定的主机身份，不禁用主机密钥检查；凭据用受控引用。节点执行使用专用身份与受限命令入口，Docker 操作属于高权限边界，不开放未认证 Docker 远程 API。
- 运行参数按结构化白名单生成，禁止拼接用户原始启动命令；限制 privileged、host 网络、宿主路径挂载和 Docker socket。需例外的应用在 M0 分类处理，不能绕过检查上线。
- 上传与分发都计算校验值并限制空间、并发与时间；材料/任务日志有保留上限，删除材料需确认无活跃任务或回退引用。资源预留结合实时系统检查，防止并发部署抢占同一端口。

- 动态白名单不等于取消白名单：独立节点授权约束与本次精确端点集合共同校验；覆盖 DNS 解析及变化、重定向、保留/元数据地址、非业务端口等 SSRF 测试。不可因 HTTP 探针成功而信任目标。
- 同一版本的路由与端点原子应用。撤销节点或端点时旧缓存不能继续放行；缓存键含环境及必要身份，不能跨用户、租户或智能体复用决策。
- 会话、CSRF、签名、重放防护和可信 Header 延续既有合同；不引入动态执行上传 Adapter 脚本。
- 对外入口与内部 upstreamOrigin 分开，拒绝将自身网关入口登记为目标造成回环。
- 新 Schema 采用显式版本协商，旧网关收到不支持版本应拒绝。先准备兼容的网关，再启用新配置；旧版本配置用于回退前核对端点兼容性。
- 初期按智能体启用网关模式；未迁移者保留已验证旧入口。迁移成功后关闭绕过入口；已经切换者不得在鉴权失败时自动回退直连。
- 不同信任来源页面评估同源风险；子域名方案如超出既有路径 ADR，应另补决策和证书/DNS接入范围，不能默认路径提供浏览器隔离。
- 存量智能体分类验证根路径、资源路径、重定向、Cookie、上传下载、SSE、WebSocket、自有登录和双用户数据隔离；明确不支持项，不能统一标记兼容。

以下是待 M0 冻结的测试验收目标，不是当前性能承诺：

| 指标 | 拟定目标或冻结要求 |
|---|---|
| 配置传播 | 在健康测试网络中，发布到目标网关全部确认不超过 5 秒；未确认保持待生效 |
| 撤权 | 新请求在 5 秒内拒绝；现有流的安全撤销另设可测上限，未落实不能通过安全 Gate |
