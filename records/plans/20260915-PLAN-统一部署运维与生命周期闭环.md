# 统一部署运维与生命周期闭环

日期：2026-09-15。用户授权：将讨论的三步方案写入计划并开发。

## 目标和边界

统一新旧项目的详情、部署、运维、下线、删除入口；底层保留旧执行方式与节点执行方式，不强制迁移或 Docker 化。完成用户从上传、运行、发布到停止、恢复、下线、资源回收的可操作流程。

本次开发不得影响现有生产实例或删除其业务数据。验收仅使用隔离测试项目。旧项目继续使用原接口；多节点项目的操作必须核对远端和网关实际状态。项目删除采用归档，业务目录保留供恢复；物理清除业务数据不在本次默认动作内。

## 第一步：统一界面与操作规则

- [x] 列表统一详情、部署、运维、更多（下线/删除）；权限不足和状态不支持区分处理。
- [x] 部署页负责材料、节点、参数、进度与版本历史；运维页负责实例、日志、启停和入口。
- [x] 将部署任务、实例运行、入口发布三个状态分别展示；多节点标签改为节点托管，避免暗示多个副本。
- [x] 禁止操作显示原因；错误不被自动刷新抹除，异步操作防重复提交。
- [x] 上传显示字节进度；后台分发/安装/检查按真实阶段显示，不伪造百分比。

组件分工：列表仅打开入口；RuntimeDeploymentPanel 组合部署内容；RuntimeOperationsPanel 组合运维内容；共享 composable 管理请求、轮询与卸载；纯函数模块给出按钮可用状态与说明。

## 第二步：生命周期管理

- [x] 持久化运维任务，幂等提交；重启恢复与失败重试保留结果和原因。
- [x] 停止/下线先撤下当前入口并等待网关确认，再停止实例；节点断连不冒充成功。
- [x] 回收实例先确认停止，移除运行载体，将业务目录归档保留；确认回收后释放控制面端口。
- [x] 失败部署重试复用材料，核对并回收旧失败实例后创建新部署，不能复用不完整环境或遗留端口。
- [x] 历史版本可复用材料创建新部署，明确节点/端口与发布步骤，不直接覆盖正在运行的实例。
- [x] 项目归档下线并回收所有实例，保留部署/运维历史及业务数据；不再调用旧本地删除接口。
- [x] 定期核对受管实例健康与远端状态，异常状态不会持续显示健康；所有写入与操作保持并发保护。

## 第三步：完整流程验证

- [x] 单元/集成测试覆盖按钮状态、材料复用、幂等、ACK 等待、节点断连、部分成功后重试、端口释放、归档数据保留、权限和中断恢复。
- [x] 节点执行器 Python/Docker 回收测试，确保不处理其他实例；中英文构建和后端完整回归。
- [x] 独立测试项目验证 47/Python、47/Docker、18/Python；18 拒绝 Docker；从页面/接口验证部署、入口、启停、重试、下线和归档。
- [x] 测试结果、未验证条件、部署/回滚步骤写入报告；未执行的线上场景保持待验收，不用单测代替。

## 实施约束

网关确认未到达时保留等待状态；远端结果未知时保留实例与端口，不盲目释放。回收只处理实例专属 systemd/container 和目录；保留原始材料和归档目录，不清理共享镜像、其他项目或数据库。

复杂依赖跨节点自动构建、高可用、自动迁移和完整告警平台另行规划。本次须明确安装失败原因和重试方式，不把人工构建依赖伪装成平台能力。

## 完成标准

三个入口语义明确，新旧项目均可从界面执行对应动作；测试项目能够完成完整生命周期，失败和断连可理解、可重试，回收后端口可复用。生产上线前保留明确回滚点；任何未完成的真实验收单独列出。
