## 首页摘要

- 要解决的问题：原有本机项目需要通过统一路径访问，同时“接入与管理”页需要清晰展示连接、项目入口和管理操作。
- 本轮交付：页面分区（R1）、旧部署路由接入（R2/R3）、仅本页使用网关入口（R4）、直连登录兼容与部署生命周期保护（R5/R6）、试点及回退证据（R7）。
- 核心约束：保留部署方式，只增加访问路由。其他页面继续沿用原 IP＋运行端口及登录流程；不批量迁移实例、不统一替换项目公共访问地址。
- 不包含：关闭原直连端口、重装节点、迁移旧项目到 18、重建旧项目为多节点实例、全量旧项目自动发布、任意自定义路径别名系统。
- 当前进度：已核对模板及关键代码；开发基线、正式路由清单和试点选择尚未完成。
- 下一步：M0 保存基线，核定原部署目标来源、既有路由及双入口认证合同，通过 Gate A 后实现。
- 待决事项：M0 由执行者选择健康、可验证的旧项目作为试点并记录依据；涉及业务数据或真实外部调用的验收内容由业务方确定，缺失时不执行相关写入。
- 排期与成本：本轮没有新增工期承诺；M0 按项目路径兼容、认证回调和数据迁移工作量估算。复用现有 47/18，不要求第三台服务器或新增付费服务。

## 背景

用户已选择“保留部署方式，只增加访问路由”，并要求暂时仅在“接入与管理”里的“进入项目”使用统一网关路径。用户还要求优化该页布局并在计划中列明影响范围。

旧项目继续运行于原进程或 Docker 容器及原端口。统一网关提供额外访问路径，目标示意为 `/agents/{agentId}/`，入口发布不触发项目重启。

## 假设

1. 原部署可从可信元数据和实际运行信息唯一对应到目标服务器与端口；无法唯一确定时禁止发布并提示选择具体部署。
2. 复用现有 `/agents/{agentId}/` 路径；`/agents/oag/` 仅在实际 agentId 为 oag 时成立。友好别名另立项。
3. 原服务可以在不迁移部署的前提下通过子路径访问；必要的项目基础路径配置列为条件项 R8，不能假定所有项目兼容。
4. 只使用现有 47/18；发现登录或业务基线故障时先记录，暂停受影响的生产验收，独立开发可继续。

## 架构扩展

### 决策驱动与方案选择

- 采用：现有路由增加原部署来源，保留进程、容器、端口及直连入口；与用户已采纳方案一致。
- 不采用重新部署成 RuntimeInstance：改变部署方式，扩大业务影响且不满足本次约束。
- 不采用逐项目增加固定 Nginx 配置：重复维护，绕开已有动态发布和授权机制。
- 不新增通用代理框架；优先复用配置版本、网关确认和审计。M0 查阅相关 ADR，记录本次扩展决策，不覆盖历史结论。
- 收益：旧项目逐个可控接入、撤销容易；代价：双入口并存、路径与登录兼容必须单独验收。

### 现状到目标变更矩阵

| 对象 | 当前 | 目标 | 代价／兼容 |
|---|---|---|---|
| 路由目标 | 显式发布绑定多节点实例 | 增加真实旧部署记录来源 | 数据迁移及来源约束 |
| 接入与管理 | 检查、说明、管理混排 | 节点连接、项目访问入口、节点管理三分区 | 只改本页行为 |
| 当前页进入按钮 | 无独立旧部署网关入口合同 | 从专用 gatewayAccessUrl 进入 | 未生效时禁用，不回退直连 |
| 其他页面 | 原访问与登录逻辑 | 保持原行为 | 发布、撤销后回归 |
| 配置与认证 | 已有动态配置、项目权限及回调 | 扩展来源，保持权限且兼容原登录 | 不能改公共回调导致直连失败 |

### 上下文与信任关系

- 管理员从控制台发起检查、发布和撤销，后端验证角色、项目归属、部署关联和版本。
- 后端根据可信记录解析目标，浏览器不能提交任意 URL、任意 Host 或未关联端口作为代理目标。
- 浏览器访问统一入口，由网关校验会话和项目授权，再转发到已登记目标。上游的独立登录机制不能被假定自动消除。
- 身份头、转发头按既有可信代理规则清理及重建，禁止直接信任浏览器伪造身份；回跳地址必须受限。
- 原 IP＋端口入口继续存在，统一网关不是唯一通道；原直连仍按原认证机制处理，不能宣称本次消除了直连绕行。
- 控制台仅展示必要配置和错误；不返回私钥、后台令牌或凭据正文。

### 目标模块与接缝

| 模块 | 修改责任 | 边界 |
|---|---|---|
| NodeDetail 及必要子组件 | 分区展示、网关状态、操作提示、独立跳转 | 不改共享项目访问 URL |
| 原部署查询与目标解析 | 确认部署归属、节点和真实端口，检查服务 | 不执行重新部署或擅自启动停止项目 |
| GatewayRouteService 及控制器 | 两类目标、发布、撤销、幂等和版本冲突 | 不伪造实例、不改旧项目业务状态迎合路由状态 |
| 路由实体、操作记录、迁移 | 增加来源和旧部署引用，保留审计 | 扩展式兼容，不删除现有实例来源数据 |
| DataPlaneConfigService | 输出可验证的旧部署目标及来源 | 保留显式路由覆盖、撤销抑制逻辑 |
| 数据面网关（父仓库 genb-data-plane-gateway/） | 若现有合同不足，最小扩展目标验证、认证回调或路径处理 | 不逐项目硬编码，不引入第二套会话系统 |
| 原部署生命周期 | 识别关联路由、端口变化与撤销确认 | 原按钮入口不变；必要阻止操作必须有明确提示 |

远程健康与网关配置调用使用测试替身做错误、超时和乱序验证，再用真实环境确认；无需为内部纯逻辑新增抽象层。

### 关键运行时场景

1. 首次接入：选旧部署 → 后台解析并检查 → 展示统一路径、当前目标和替换影响 → 发布新版本 → 等待网关确认 → 才提供进入按钮。
2. 已有有效路由：展示原来源和目标，不重复创建；若切换目标，先检查新目标，版本冲突返回刷新提示，不能静默覆盖其他发布操作。
3. 访问：未登录进入既有认证流程；无权限拒绝；已授权转发。上游失败给明确不可用提示，不跳回直连绕过网关。
4. 撤销：写撤销版本 → 等待网关确认 → 显示已停用。不得通过直接删记录让历史派生路由重新生效。
5. 端口变化：发布前检查新目标，确认生效后更新页面；失败保留原有效路由，但必须说明原服务是否仍实际存活，不能承诺业务持续可用。
6. 停止／删除：对关联路由先撤销并确认，再停止或删除；确认超时则阻止破坏性步骤。审计保留项目和部署来源快照。
7. 网关失联或配置确认超时：显示待确认／确认超时，可重查；数据库写入成功不能显示访问成功。

### 接口、数据与状态

建议合同，M0 固定实际路径后更新本计划：

| 能力 | 建议接口 | 主要规则 |
|---|---|---|
| 当前页项目入口列表 | GET `/v1/runtime-nodes/{nodeId}/project-access` | 返回来源、部署 ID、实际检查状态、路由状态和 gatewayAccessUrl；分页；管理权限 |
| 检查旧部署目标 | POST `/v1/legacy-deployments/{deploymentId}/gateway/check` | 后台解析目标；不安装、不重启；检查结果带时间和目标版本 |
| 发布旧部署入口 | POST `/v1/legacy-deployments/{deploymentId}/gateway/publish` | expectedVersion＋idempotencyKey；复核目标，防止检查后端口已变化 |
| 撤销旧部署入口 | POST `/v1/legacy-deployments/{deploymentId}/gateway/withdraw` | 校验当前目标归属；复用版本确认和审计 |

- 路由唯一性保持“一项目一个当前生效目标”；不增加自定义入口名称输入。
- 建议增加 sourceType（RUNTIME_INSTANCE／LEGACY_DEPLOYMENT）及 legacyDeploymentId，旧 instanceId 对旧部署允许空；数据库检查约束保证两类引用互斥且必有其一。操作记录同步扩展来源；具体 DDL 在 M0 核对迁移框架后确定。
- 已有记录回填为实例来源，不创建占位实例；上线前检查现存数据是否满足回填假设。
- 独立返回 gatewayAccessUrl，保留原 accessUrl、launchUrl 及默认行为；如采用共享组件，新增选项默认沿用原访问模式。
- 路由状态复用 UNPUBLISHED、PENDING_GATEWAY、APPLIED、WITHDRAWING、WITHDRAWN；实时健康与检查错误单独表达，不能用路由状态代替健康。
- 参数错误、无权限、记录不存在、版本／目标冲突、依赖超时分别给出可理解提示；重复幂等键只能用于同操作、同目标和同操作人。
- 超时、响应大小、流式限制继承现有合同；M0 记录实际配置，不在计划中编造可用指标。

### 安全、缓存与故障模型

- 复用现有网关认证和项目授权；针对旧项目验证未登录、无权限、退出、会话过期及撤权，不以管理员访问成功代替权限验收。
- 核对登录回调影响：旧部署路径不能无条件调用会覆盖公共 callbackUrl 的发布逻辑。优先复用网关独立回调；若现有认证合同无法保持双入口，先补兼容设计再发布。
- 目标白名单与配置快照一并验证，限制协议、地址和端口，拒绝元数据地址、未登记目标、重定向逃逸及路径绕行。
- 不新增缓存层；复用配置版本和失效通知。M0 实测配置应用和撤权窗口，保持既有上限；当前代码的确认新鲜度条件为 15 秒，这不是本轮承诺的撤权时间。
- 检查失败不得发布；确认失败不得误报；重试有界，不自动无限重发或吞掉权限错误。
- 数据面身份校验不等于上游业务数据隔离；本轮不宣称解决旧项目多用户共享状态问题。

### 兼容、迁移和退役

- 先做兼容数据扩展，再部署能够理解两类来源的程序，最后按项目启用旧部署路由。
- 对现有派生路由逐项登记基线，接管时不把“已可访问”错误标为完全未接入。
- 数据面若需协议升级，先发布可兼容旧快照的读端，再发布新来源配置；旧版本不得误认或放行未知目标。
- 首轮只接入一个合适旧项目，后续逐个检查，不在首次发布中自动启用全量项目。
- 原 IP 端口继续保留。撤销新增入口与恢复接入前历史网关路由是两种操作，必须分别记录。

### 质量场景与生产就绪

- 测量变更前后页面首屏、普通请求、配置应用、必要的流式／WebSocket 行为；与同环境基线比较，差异须说明，不能只看首页 HTTP 200。
- 记录配置版本、网关应用版本、目标、最近检查、错误原因和操作人，支持定位失败阶段。
- 本地毕业：需求表对应专项及回归通过；生产毕业：真实旧项目权限、业务路径和其他页面直连回归通过，且有路由回退证据。

### M0：验证基线与合同

### M2：优化页面并接入独立访问地址

Gate C：R1/R3/R4 的本地浏览器、构建及回归通过；页面失败状态与后台状态一致。

### M3：真实试点、发布与总验收

Gate D：需求表所有必须项和已触发条件项完成；生产证据真实、回退可执行。更新 `CURRENT_TASKS.md`、`records/RECORDS_INDEX.md`、操作说明、报告和发布记录。Gate 是客观技术条件，不新增重复人工审批流程。

## 回滚与恢复

1. 发布前保存每个试点原路由（含派生来源）、配置版本、公共访问／回调字段、部署目标及数据库备份；备份前后端和网关产物及配置。
2. 功能异常先停止新增发布，撤销本轮新增路由并等待网关确认；如果接入前已有路由，显式恢复原目标并发布新版本，而不是删除记录或倒退版本号。
3. 恢复本页原访问行为和必要程序／配置；如涉及数据面协议，先确保输出快照与拟回退程序兼容。验证多节点、直连登录和旧网关路径。
4. 增量数据库字段优先保留，不直接 DROP。旧后端不理解新来源或空 instanceId 时，先导出并清理／转换本轮旧部署记录，使旧版可读取，再恢复旧程序；不强行把旧部署填成伪实例。
5. 已发生端口变更时，先核实原服务仍存在，不能将路由回指已被其他项目占用的端口。
6. 项目路径配置若因 R8 调整，按独立备份恢复并验证直连；不能以恢复网关代替项目自身回退。

## 风险与阻塞条件

| 风险／触发信号 | 影响 | 缓解及停止条件 |
|---|---|---|
| 公共回调被覆盖，直连登录失败 | 违反用户核心范围 | R5 未通过禁止生产发布 |
| 端口无法唯一解析、运行记录失真 | 可能代理错误项目 | 以真实检查及归属为准；不能确定则禁止接入 |
| 显式路由接管既有派生路由 | 可能意外切换／撤销旧入口 | 保存有效路由，确认切换，显式恢复 |
| 网关不认可旧部署目标 | 入口写入但不能转发 | 核对允许目标和快照合同，等待真实确认 |
| 资源／接口写死根路径或 IP | 首页正常而业务失败 | 触发 R8，逐项目适配；未通过不展示可用 |
| 数据迁移或旧版本不兼容 | 控制端／网关启动失败 | 增量迁移和恢复演练，先兼容后发布 |
| 无可用试点、有效业务账号或授权场景 | 生产验收无法完成 | 仅完成独立开发；R7 保持未通过，不伪造验收 |
| 当前环境已有登录或网络故障 | 无法区分回归与旧故障 | 保存证据，修复基线后继续受影响的生产 Gate |
