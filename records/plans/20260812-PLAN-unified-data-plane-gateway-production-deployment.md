# GenB统一数据面网关生产部署任务计划

- 日期：2026-08-12
- 状态：待执行；受后端容量Gate阻塞
- 负责人：GenB平台、服务器运维与试点业务负责人
- 前置条件：先完成本地方案实现Gate F，再完成上线检查与服务器治理Gate D
范围：现有两台服务器上的可回滚、限流、逐步切换上线
依赖：维护窗口、部署授权、试点用户和已验收产物

## 背景

当前服务器只能支撑单实例、小规模受控上线：前端机资源有限，后端机可用内存尚可但已有较多业务负载，且需先解决磁盘风险。因此部署采用前端Nginx统一路由、后端单实例轻量网关和专用Redis，不一次迁移所有智能体，不宣称高可用。

本计划是三项任务中的第三项。它不包含补做本地功能或补做服务器治理：任何实现缺陷必须退回方案实现计划，任何容量、安全或资产归属问题必须退回上线检查计划。两个前置Gate均有效时才允许开始D0。

## 假设

- 已取得服务器部署授权并确定维护窗口、负责人和业务通知范围。
- 所有镜像和配置已在本地/测试环境通过实现计划Gate F。
- 后端磁盘低于80%且不少于20GiB可用，现有项目健康。
- 一期限制为20活跃用户、100登录会话、20组件并发，超出时拒绝或排队。
- 回滚仅用于发布安全；新入口验收完成后删除对应旧正式入口，不长期双版本。

## 当前事实与失败基线

- 2026-08-12服务器只读证据仅支持小规模单实例方案，不支持宣称高可用。
- 核心组件模板、三个独立组件服务和18714当前未部署到服务器。
- 生产GenB JAR尚不包含本轮Manifest导入和Agent SSO实现。
- Nginx尚无`/agents/{agentId}/`和`/component-api/`正式数据面路由。
- 上线检查与方案实现均尚未开始，因此当前不满足部署前置条件。
- 固定执行顺序为“本地方案实现Gate F → 上线检查Gate D → 生产部署Gate A-E”，不得并行切流或倒序执行。

## 成功标准

- 网关和专用Redis按资源、安全、日志和健康配置启动，端口不向公网暴露。
- Nginx配置测试通过，现有门户、GenB、GenC、GenO入口零回归。
- 一个试点智能体和一个核心能力先完成白名单用户验收，再逐步扩大。
- 登录、退出、撤权、对话、SSE、三个当前组件和外部服务Adapter运行正常。
- 上线观察期内错误率、P95、CPU、内存、磁盘和连接数均在阈值内。
- 旧入口按智能体逐个下线，所有部署包、配置、哈希、验证和回滚点有记录。

## 修改范围

- 后端部署目录、Docker Compose/运行配置、内部网络、专用Redis和网关容器。
- 前端Nginx新增`/agents/`和`/component-api/`路由及流式代理参数。
- GenB生产控制面迁移、网关身份和首批配置发布。
- 试点智能体入口、组件绑定和逐步迁移清单。
- 监控、告警、备份、回滚和部署记录。

## 明确不处理

- 不在本次部署中迁移所有14个组件。
- 不开放Redis或网关内部管理端口到公网。
- 不直接修改同事自行部署的服务或其数据库。
- 不在无备份、无哈希、无回滚命令时替换生产文件。
- 不在指标异常时继续扩大流量。

## 交付物

- 带哈希的网关镜像、配置清单和Secret引用清单。
- 专用Redis、内部网络、资源限制、健康检查和监控配置。
- 经测试的Nginx配置、备份和精确回滚文件。
- GenB迁移与配置快照、试点和分批迁移清单。
- 部署记录、上线报告、运行手册和回滚演练证据。

## 执行步骤

### D0：部署前门禁与冻结

1. 复核两个前置计划Gate证据、维护窗口、当前Git提交和产物哈希。
2. 保存Nginx、GenB配置、数据库迁移状态和当前入口的只读快照。
3. 备份将修改的精确文件和配置；验证回滚命令不依赖现场临时编辑。
4. 再次检查磁盘、内存、端口、容器健康和统一登录。

Gate A：任何前置Gate、备份、磁盘或现有健康检查不满足，立即停止部署。

### D1：旁路部署

1. 创建后端内部Docker网络和专用Redis，不绑定公网端口。
2. 部署网关容器，设置1CPU、1GiB、日志轮转、健康检查和自动重启。
3. 导入网关机器身份和Secret引用，秘密不写入镜像、Git或日志。
4. 只通过服务器内部地址验证控制面、缓存和三个组件，不修改公网路由。

Gate B：网关、Redis、GenB和组件内部链路通过，资源稳定后才允许配置Nginx。

### D2：Nginx与白名单试点

1. 备份实际生效配置并执行`nginx -t`。
2. 增加统一路由、流式转发、上传限制和安全Header，先不覆盖其他项目路径。
3. 仅为测试用户和一个试点智能体启用新入口。
4. 完成真实浏览器登录、退出、刷新、SSE、对话和一个组件能力验收。

Gate C：现有入口全部回归，试点链路和安全检查通过，观察期无异常后才扩大范围。

### D3：逐步迁移

1. 按“无状态→可读取身份→独立实例→暂不兼容”清单迁移智能体。
2. 每批只迁移少量智能体，发布后观察CPU、内存、错误率、P95、Redis和磁盘。
3. 核心组件按Adapter逐个启用；异常实现只回滚该绑定，不影响其他能力。
4. 超过资源阈值、缓存错误或权限异常时立即停止扩量并执行回滚。

Gate D：目标智能体和能力完成用户隔离、稳定性与业务验收后，才能关闭其旧入口。

### D4：单入口收口与交付

1. 删除已完成迁移智能体的公网裸端口入口和GenB旧跳转，不保留正式双入口。
2. 保留明确期限的配置/镜像回滚点，不保留可被用户访问的旧页面。
3. 完成部署记录、运行手册、监控阈值、故障联系方式和扩容触发条件。
4. 连续观察并形成上线报告，区分已迁移、暂缓和不兼容智能体。

Gate E：单入口、监控、回滚演练、文档和所有已迁移业务验收完成后，部署才标记完成。

## 验证与监控阈值

- 健康：网关、Redis、GenB、试点智能体和组件连续健康。
- 资源：网关内存不超过限制的80%，后端可用内存保持3GiB以上，磁盘低于80%。
- 性能：正常代理新增P95延迟目标小于50ms；模型和外部组件耗时单独统计。
- 稳定性：5xx低于1%，鉴权拒绝可解释，无无限重试和连接泄漏。
- 安全：真实地址、API Key、Cookie、Token和对话正文不出现在访问日志。
- 回归：`/portal/`、`/genb/`、`/journey/`、`/geno/`及现有API保持可用。

## 回滚

1. 停止扩大流量并将试点路由恢复到部署前Nginx配置。
2. 恢复上一个GenB配置快照和组件绑定版本。
3. 将网关恢复到上一个已验收镜像；必要时停止网关但不删除数据卷。
4. 验证统一门户和现有三项目恢复后再分析问题。
5. 回滚不得直接删除Redis数据、数据库表或新旧镜像。

## 风险

- 单实例网关和专用Redis仍是单点，当前上线级别是可恢复而非高可用。
- Nginx动态路径代理配置错误可能影响其他项目，必须精确匹配并全量回归。
- 旧智能体真实端口若继续公网开放，注入身份Header可能被绕过；迁移后必须限制直连。
- SSE和大文件可能持续占用连接和带宽，必须设置独立超时、并发和大小限制。
- 服务器资源达到阈值时不能用“继续观察”替代停止扩量；应增加独立网关服务器后再提升规模。

## 状态与记录规则

- 本地方案实现Gate F和随后执行的上线检查Gate D未全部通过时，本计划保持待执行。
- 每次只执行一个部署Gate；任何健康、资源或权限异常立即停止扩量。
- 所有服务器、Nginx、Redis和数据库操作逐项写入部署记录，不事后补记。
- Gate E通过后才标记完成，未迁移智能体必须明确列为暂缓或不兼容。
