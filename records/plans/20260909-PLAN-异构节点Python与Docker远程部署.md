## 目标流程

管理员配置节点允许的项目类型 → 平台探测实际运行环境 → 上传 Python ZIP 或 Docker 镜像归档 → 选择兼容节点 → 持久化部署任务 → 远程准备、启动、健康检查 → 发布并确认网关入口。

Python 直接采用独立虚拟环境与 systemd 管理，不自动转为 Docker。节点实际具备能力和管理员允许能力分开记录；缺少运行环境、管理员禁用、节点不可用任一条件成立均拒绝部署。前端过滤与后端校验同时实施。

## 开发顺序与验收

1. **节点能力**：pythonAllowed/dockerAllowed 与 pythonAvailable/dockerAvailable 分离；管理员修改许可需版本检查；接口、持久化和页面均验证 Python-only 节点拒绝 Docker。
2. **受控远程执行**：统一 SSH 入口、固定程序、JSON 参数；节点本地策略再次限制类型、端口和资源。Python ZIP 解包拒绝目录穿越、链接、超限；独立 venv；依赖安装和应用执行使用非 root 用户；systemd 管理启动、停止、重启和日志。Docker 保留归档导入路径，禁用节点不能调用。
3. **任务与材料**：流式上传、摘要、任务 ID、实例 ID 和节点 ID；任务状态持久化；重复请求复用结果，超时先查询远端，不盲重试。部署失败不覆盖既有运行实例。
4. **管理界面**：节点类型及检查结果，部署类型、目标节点、结构化入口参数，进度、状态、日志与启停。旧未迁移部署兼容，新实例不走本地执行接口。
5. **网关接入**：继续原计划的端点合同、原子快照、应用确认与稳定入口；未完成不得把实例启动误报成网关可访问。
6. **验证和部署**：本地后端、节点执行器、前端测试与双语构建；备份与数据库迁移演练；47 后端与18管理界面发布；18 安装受控 Python 节点程序及必要环境；小型测试项目验证平台远程链路后交给用户上传 FIBO。

## 资源与安全边界

- 18 不安装 Docker、JAR、数据库或本体中间件；Python 环境如需升级采用并行安装，不替换系统 Python。
- 首次试点一实例，应用内存默认 192 MiB、最高 256 MiB，CPU 上限 50%，任务并发 1；部署前检查系统可用内存、磁盘、端口，保留原前端服务资源。阈值不足明确失败，不清理其他项目或盲目扩容。
- 仅部署管理员可上传和执行项目。项目依赖安装也可执行代码，必须非 root 并限制资源；venv 不是安全隔离替代品。
- 只接受结构化入口（例如 Python 脚本或 ASGI 模块）、端口和批准的环境引用；不接收任意 shell 命令，不在日志或文档保存凭据。
- 47→18 管理连接及网关业务连通要实测，不能以本机可 SSH 替代。
- 变更前备份；Nginx 变更先 nginx -t；回归统一登录、各平台入口和现有 FIBO 隧道。出错回滚本次具体服务和产物，不覆盖他人配置。
