## 背景

平台已能选择 18/47 部署 Python 或 Docker 项目，并通过统一入口访问。但节点管理藏在项目部署弹窗内，新节点仍需运维准备；没有按服务器展示资源、项目数和实例状态的完整总览。

本轮重点是让管理员能够回答：有几台服务器、每台支持什么项目、还能部署多少、哪些项目正在运行、异常发生在哪里。保留现有远程部署和网关，不重新建设执行链路。

### 上下文与信任关系

- 管理员浏览器只调用 GenB 后端；后端验证管理角色，不向浏览器发 SSH 密钥。
- 47 控制面通过已登记且校验主机密钥的 SSH 连接调用节点固定程序；节点只接受规定 JSON 动作，禁止任意 shell。
- 节点采集整机资源并返回快照，不读取智能体业务正文、用户输入或环境变量中的秘密。
- 网关业务链路独立于管理 SSH：由实际 Nginx 代理节点连接目标或批准的隧道；身份由既有门户/网关验证。
- 业务请求的身份 Header 按既有网关合同清除并重建；监控接口不增加信任客户端自报身份的分支。
- 节点登记和网络地址修改属于管理员操作；无权限用户不能读取内部地址、日志或部署材料。

### 关键运行时场景

1. 新增节点：运维核验系统、资源和主机指纹 → 安装固定执行器与本地策略 → 配置 47 管理连接和实际网关业务通路 → 管理员登记 → 环境/连接检查 → 选择许可 → 小样例部署与访问 → 标记可部署。
2. 资源采样：调度器选择节点 → 有界并发发送只读 metrics → 校验 schema、nodeId 和时间 → 保存有效样本 → 聚合数量 → 页面显示采样时间。失败保留最后样本并标记过期，不能写成零资源。
3. 暂停与排空：管理员暂停新部署 → 后端同时拒绝新建任务和入口切换到不允许的目标（规则在合同固定）→ 保留现有运行与必要启停/恢复 → 提示受影响项目 → 全部实例和入口依赖清理后才允许退役。暂停新部署本身不撤下现有入口。
4. 部署诊断：上传完成 → 校验材料与节点能力 → 检查资源、端口和必需工具 → 安装与启动 → 健康检查 → 单独发布入口。每阶段失败保留具体原因和可执行下一步，不盲目重试不确定结果。
5. 登录与访问：用户进入统一路径 → 门户/网关确认身份权限 → 路由到健康实例；会话过期要求登录，撤权后按现有撤销合同拒绝。控制面/缓存异常不能绕过鉴权访问裸端口。
6. 故障恢复：节点断连显示失联和最后观测时间；端口不释放、实例不自动删除；恢复后重新核对并清除恢复告警，不把旧数据当成新数据。

### 接口、数据与状态

以下新增接口是设计草案，必须在 M0 核对现有 OpenAPI，冻结后才能实现；路径均相对现有 API 前缀。

| 接口 | 方法、身份 | 请求 / 响应与约束 |
|---|---|---|
| `/runtime-nodes` | 现有 GET/POST，管理员 | 保留登记合同；扩展分页、能力、管理状态和观测状态筛选 |
| `/runtime-nodes/{id}` | 拟增 GET/PATCH，管理员 | 详情、名称/说明编辑；expectedVersion 冲突返回 409；可信目标修改通过独立接入核验 |
| `/runtime-nodes/{id}/lifecycle` | 拟增 POST，管理员 | 暂停、恢复、排空、退役；幂等键、expectedVersion；依赖冲突返回 409 并列出影响项 |
| `/runtime-nodes/{id}/metrics` | 拟增 GET，管理员 | 返回最新值、采样时间、过期标志；历史限定时间范围和每序列最多 1,000 点 |
| `/runtime-nodes/{id}/workloads` | 拟增 GET，管理员 | 分页项目/实例、版本、运行/健康/入口状态；不得跨权限泄露日志 |
| `/runtime-nodes/{id}/checks` | 拟增 POST，管理员 | 异步接入检查，返回任务 ID；结果包括管理连接、执行器、环境、磁盘、业务路径，单步失败可定位 |
| 节点 SSH `metrics` | 固定 JSON 动作，控制面身份 | protocolVersion、nodeId、sampledAt、bootId、CPU 计数器、内存及磁盘字节数；回复上限 64 KiB；不传业务正文 |

- 管理生命周期、健康观测、Python/Docker 许可分开存储；禁止用一个 enabled 字段表达所有状态。生命周期至少 ACTIVE、PAUSED、DRAINING、RETIRED；观测至少 UNKNOWN、ONLINE、STALE、UNREACHABLE，具体映射在合同中固定。
- 样本唯一键 `(nodeId, sampleId)`；同时保存节点采样时间和控制面接收时间。节点时钟异常时提示偏差，不能用未来时间掩盖失联。
- CPU 使用率由相邻累计计数差计算，节点重启或计数回退时首点为空；不把 load average 当 CPU 百分比。
- 内存：总量、可用量、使用量 `total - available` 和百分比；磁盘按部署数据目录所在文件系统展示，不冒充整机所有磁盘。单位明确为 MiB/GiB。
- 项目数：该节点存在未回收实例的 distinct agentId；实例数：未回收 instanceId 数。运行实例数按 RUNNING/HEALTHY 统计，过期记录标明“最后观测”，失联时另列未知数。
- 同一项目多个版本计一个项目、多个实例；跨节点同项目在各节点分别计数，平台总项目数去重。失败任务但尚无实例单列，不计入运行实例。旧本地部署单列“旧模式/未纳管”，不可默认算零或混入节点统计。
- 原始样本拟保留 24 小时，5 分钟聚合保留 7 天，告警事件保留 30 天；为设计初值，M0 做容量测算后确认。配置及审计保留沿用现有规则，不随节点退役自动删除。
- 错误沿用统一结构并增加稳定错误码与检查阶段；400 参数、403 无权限、409 状态/版本冲突、503 节点暂不可达。凭据和完整命令不进入错误正文。

### 安全、缓存与故障模型

- 复用现有角色验证、会话与 CSRF 约定；节点地址仅从可信目标取得，防 SSRF；禁止浏览器提交 SSH 命令、私钥或任意 URL 探测目标。
- 管理变更使用版本控制和幂等键，记录操作者、节点、变化前后及结果；秘密仅保留引用。
- 监控采用数据库最新样本作为读模型，不新增 Redis/L1 双层缓存。页面可以保留最近结果，但始终展示采样时间与过期状态。
- 拟每 30 秒采样一次、单节点 5 秒超时、最多 2 个节点并发；只读失败不在同一轮密集重试。90 秒无成功样本标记过期，连续失败触发失联事件；恢复需有效新样本。
- 监控故障不应占满部署线程池，不阻塞既有智能体业务请求；不因采样失败自动重启或迁移项目。
- 网关现有会话、缓存键、撤权时限和故障策略保持既有合同；M0 抽取具体值写入验收基线，本轮不重新设定、更不延长安全宽限。

### 兼容、迁移和退役

- 先部署兼容新旧协议的控制面，再升级节点。旧执行器没有 metrics 时显示“不支持监控/待升级”，部署能力不应被误判为不支持。
- 节点能力遵循“实际支持且管理员允许”；18 无 Docker 时保持禁用。执行器升级不替换系统 Python，不修改既有实例目录。
- 旧项目迁移纳入本轮盘点、适配检查和一个获准样例的试点；不承诺所有项目自动搬迁。原数据、环境依赖、自有登录、资源绝对路径、回调和 WebSocket/SSE 分别核对。
- 试点过程新旧实例并存；新入口业务和隔离验收通过后才撤旧入口。旧实例退役、数据保留/复制方案要明确，不能把复用代码包当成恢复业务数据。
- “网页能打开”与“用户数据隔离正确”分别验收。未通过身份隔离的项目只能标记兼容待完成。

### 质量场景与生产就绪

以下是拟验收目标，不是当前系统性能事实：

- 以 10 个隔离模拟节点、100 个实例测试调度；健康网络下节点数据 95% 在 60 秒内更新；90 秒过期标识准确。
- 节点列表/详情 API 在上述样本量下 p95 ≤ 2 秒；历史图查询 ≤ 1,000 点/序列；大结果分页。
- 18 采集程序单次峰值 RSS 目标 ≤ 32 MiB，5 分钟平均附加 CPU < 2 个百分点；超标调整采样或实现，不压缩业务配额掩盖问题。
- 拟默认 CPU 或内存使用率持续 5 分钟 ≥ 85%、部署磁盘使用率 ≥ 90% 产生站内告警事件；连续恢复 2 分钟关闭，重复状态合并。阈值可配置，磁盘硬部署保护仍沿用节点策略。
- 首版仅站内告警列表和恢复记录；邮件、短信、企业通信平台通知单列后续扩展，不默认外发。
- M0 记录数据库容量预算、样本增长量和清理耗时，生产必须验证保留期清理；本地模拟通过不代替 18/47 资源实测。

## 回滚与恢复

- 开发回退仅撤销本任务已提交的精确文件，不覆盖其他工作树改动。
- 数据库采用新增表/可空字段优先；升级前备份并验证恢复。旧版本不认识的新状态不得直接交还处理，先暂停新增管理变更并核对活动任务。
- 出现采样开销异常，先关闭新采样/告警开关，保留既有部署与业务；再依次回退前端、节点程序和兼容后端。保存新表用于前向修复，避免直接删表回滚。
- 网关配置更改逐项备份、校验后应用；恢复对应配置和已确认路由版本，不把过期权限快照作为回滚方案。
- 项目试点迁移以入口切回已验证旧实例为首选恢复方式；存在新版本数据写入时，先按项目数据方案处理一致性，不能仅切流量宣称恢复完成。
- 节点退役不物理清除业务数据；密钥吊销需确认无其他管理或隧道依赖。回滚恢复的是配置与可用性，不自动恢复已回收实例。

## 风险与阻塞条件

| 风险 / 信号 | 影响 | 缓解与停止条件 |
|---|---|---|
| 18 内存紧张、采样 RSS 或 CPU 超标 | 影响既有项目 | 缩小响应和采样开销；未满足资源目标不向 18 发布 |
| 可信 SSH 可达但业务路径失败 | 部署成功但访问失败 | 接入检查分开验证；未确认入口不显示可访问 |
| 将本机监控展示为全部节点 | 误导容量判断 | 指标必须带 nodeId、来源和时间；对照两节点数据 |
| 统计混淆项目、版本、实例和旧部署 | 数量不可信 | 使用固定口径和重复项目样例；未知范围显式展示 |
| 历史样本持续增长 | 数据库或磁盘压力 | 保留期、聚合、清理和容量预算必须验收 |
| 缺少授权测试账号/旧项目材料/第三节点 | 无法完成对应真实验收 | 阻塞 Gate F 或相应真实节点验收，不用模拟结果替代 |
| 自动安装复杂依赖改变系统环境 | 破坏现有业务 | 首版预检与诊断优先；系统变更单独核对方案 |
| 业务流式接口或自有登录不兼容 | 页面可开但功能不可用 | 兼容清单逐项实测；未通过项目不退役旧入口 |

## 状态与记录规则

- 当前实施状态为“执行中”；开发与本地测试不等于生产完成。Gate C—F 及最终 Gate 的剩余证据按阶段表继续补齐。
- 实际开始 M0 才改为“执行中”；每个 Gate 记录日期、版本、环境、证据及剩余问题，禁止提前勾选。
- 范围、阈值、接口、拓扑或假设发生变化，先更新计划及 ADR，再实施变更。
- 允许按已完成模块汇报“节点管理已发布、监控待验收”等准确状态，不用一个总完成标记覆盖缺口。
