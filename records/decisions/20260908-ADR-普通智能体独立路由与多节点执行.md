# 普通智能体独立路由与多节点执行

- 状态：本地实施决策，2026-09-08；延续 20260812 网关 ADR。
- 依据：用户已授权 20260907 多节点计划，首版只做 Docker 归档、受控 SSH 和单主实例。

## 决策

1. 路由发布独立于组件绑定。独立路由记录优先于历史绑定推导路由，撤下的记录也保留，以阻止历史路由重新出现。
2. 用户入口与 upstreamOrigin 分开。已登记运行实例才允许发布；草稿和运行状态不直接开放用户访问。
3. 新快照版本使用 1.1，携带精确端点；网关兼容旧 1.0。端点还必须落在运维设定的获准节点网络中，首版节点业务地址仅支持字面 IPv4，拒绝 DNS、重定向、链路本地及元数据地址，避免解析变化。
4. 节点连接使用服务端受控 SSH 别名及固定主机身份检查。操作请求为 JSON，不接受远程 shell 命令。节点侧使用标准库 Python 受限程序实现参数检查、任务幂等和 Docker 归属校验，需要 Python 3 运行环境，随节点安装说明明确列出。
5. 新能力先只开放 ADMIN/SUPER_ADMIN，新增节点需系统管理员授权。非管理员不能通过新接口登记节点、上传、执行任务或读取日志。既有旧部署接口继续服务未迁移对象，不能作为新纳管实例的旁路。
6. 管理中心保存任务状态，节点保存实际操作结果；超时标记 UNKNOWN 并查账，不盲重放创建。已发布实例停止前撤路由并等网关确认。
7. 第一轮默认试点无状态、一个运行端口、无宿主挂载和特权参数；需要 GPU、数据卷或特殊启动参数的应用先列为待适配，不能静默放宽执行边界。

## 验收分层

本地 Gate 以隔离 H2、测试执行器和网关合同为基线，不依赖现有生产数据库。外部节点缺失仅阻塞真实远程及双节点 Gate，不把不可用资源伪造为通过；必要时记录本地子门禁与整体门禁分别状态。

拟冻结测试负载为 20 并发用户、20 条路由，10 次配置发布；本地配置处理 p95 不超过 200ms（不含上游业务耗时），正常发布不导致原路由请求失败；真实环境再验证 5 秒配置/新请求撤权指标。已存在长连接的撤权仍需真实代理层方案，不能以请求鉴权通过替代。
