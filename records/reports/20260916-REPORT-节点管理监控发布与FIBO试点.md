## 本轮发现并处理的问题

1. 详情轮询误把分页对象当数组调用 `find`：改为使用节点数组，成功刷新后清除旧错误；重新发布中英文管理端，生产回归通过。
2. 端口空闲检测将停止后的 TIME_WAIT 判为占用：加入 SO_REUSEADDR。Linux 真实套接字测试同时验证 TIME_WAIT 可复用、活动监听仍拒绝。47 首次重试失败的原始响应未保存，不能断言它是该次失败的唯一原因；修复后从平台恢复并完成重试验收。
3. 内存/磁盘/端口预检失败缺少明确提示：节点返回允许列表内错误码，后端保存 FAILED 与具体原因；未识别响应或网络中断仍保守保持 UNKNOWN。节点原始错误不直接暴露给用户。
4. 生产后端缺少网关会话失效配置：补齐失效服务地址和现有网关凭证，验证 CONFIG 失效请求返回 202；三类样例的已登录会话在撤权后均被拒绝。凭证仅保存在服务器 root 可读配置，未进入仓库。
5. 撤权后重新授权，新会话仍被 L1 的旧范围失效记录拒绝：新增会话创建时间，范围失效只阻止其发生前的会话。兼容旧 Redis 记录，对缺少创建时间的旧记录保守拒绝。红色用例先复现，修复后验证重新授权成功、旧会话不复活、二次撤权有效、Redis 失败时仍拒绝。已发布 47 网关，FIBO 实际再授权访问通过。

浏览器期间遇到过空响应 502，响应含代理连接头；随后自动刷新恢复，18 Nginx 对应接口连续 200，错误日志未出现同时段上游错误。推测与客户端代理链路有关，未据此宣称根因已确定。另有 FIBO favicon 404，业务 API 正常。发布重启窗口的短暂后端连接拒绝也有记录，不声称无中断发布。
