# 任务：核心组件需求确认文档与统一门户登录动效性能优化

### 1. 背景

五大系统/14组件的讨论中混入了项目拆分、HTTP/MCP和数据库等技术实现问题，不利于领导先确认业务结构和功能效果。同时，Genesis统一门户登录页在鼠标移动和输入时出现明显卡顿，会议曾怀疑登录动效造成主线程压力。

### 2. 目标

- 形成只聚焦总体结构、组件功能边界、用户效果和一期验收的确认清单。
- 建立可重复的浏览器性能测试，确认登录页卡顿是否由动效造成。
- 保留与鼠标无关的固定波浪动效，降低背景绘制对鼠标和输入响应的影响。

### 3. 范围

- 新增核心组件结构、规划与推理引擎、短期记忆/工作台确认文档。
- 优化 `PortalWaveBackground.vue` 的全屏Canvas循环。
- 新增真实浏览器性能回归脚本。
- 不修改登录接口、登录表单、平台授权、页面主体布局和组件业务逻辑。

### 4. 完成标准

- [x] 确认文档明确排除项目拆分、部署数量、HTTP/MCP和数据库等具体实现。
- [x] 文档覆盖总体结构、规划组件、短期记忆工作台和一期效果验收。

### 5. 根因和修改

根因不是“跟随鼠标重绘”：原实现没有监听鼠标位置，而是在全屏Canvas上持续约60帧重绘。每帧包含42行、112列网格、约1650个圆点、大量三角函数和模糊阴影；2×屏幕像素密度下实际画布约为3840×2160。“减少动态效果”模式也没有停止该循环。

本次修改：

- 将固定动画目标绘制频率限制为30 FPS。
- 将背景像素比上限限制为1.5，避免高DPI设备无上限放大画布。
- 网格从42×112降到24×72，装饰粒子从150降到72，降低阴影半径。
- 缓存Canvas上下文和尺寸，不再每帧重新获取。
- 页面不可见时停止动画，重新可见时恢复。
- `prefers-reduced-motion: reduce` 时只绘制一帧静态背景。
- 动画始终与鼠标位置无关。

### 6. 性能验证

测试条件：1920×1080视口、2×设备像素比、4×CPU降速、页面内部连续三秒Pointer事件、真实Chrome。

| 指标 | 优化前普通 | 优化后普通 | 优化后减少动态效果 |
|---|---:|---:|---:|
| 帧间隔中位数 | 97.1 ms | 12.1 ms | 6.1 ms |
| 帧间隔P95 | 121.1 ms | 42.5 ms | 6.2 ms |
| 三秒Canvas圆点绘制 | 64,584 | 41,004 | 612 |
| 三秒清屏次数 | 39 | 67 | 1 |
| 超过34ms的帧 | 27/27 | 26/151 | 0/495 |

优化前由于每个绘制帧本身过重，即使实际只完成约13 FPS，所有采样都超过34ms；优化后浏览器能在同样压力下调度更多交互帧，普通模式中位间隔下降约87.5%，减少动态效果模式完全停止循环。
