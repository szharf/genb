## 已实现

1. 管理员可查询及登记运行节点。目标由服务端 `runtime.nodes.trusted-targets` 的 SSH 别名映射决定，不接受浏览器提交任意目标。登记后 UNKNOWN、禁止部署，必须由后续实际预检改变状态。
2. 普通用户不能查询或登记节点。节点 ID、SSH 别名及业务地址分别去重，避免同一连接目标重复登记后绕过节点端口唯一性。
3. 普通智能体的独立 PUBLISHED 路由进入数据面快照，不要求绑定核心组件。使用 `upstreamOrigin`，不把对外 `accessUrl` 当作内部目标。
4. 独立撤下记录覆盖历史绑定推导路由，后续发布不复活被撤下的入口。
5. 每个配置版本保存完整 JSON 快照；版本增长、快照持久化和发布事件保持同一事务。读取已发布版本不会重新拼接当前数据库内容。
6. 增加节点、实例、路由、快照的实体与 PostgreSQL 迁移脚本。实例目前仅为数据结构，不提供可用的远程操作接口。

接口合同：`contracts/genb-runtime-nodes.openapi.json`。配置示例仅供后续隔离环境配置，不已写入 application.yml：

```yaml
runtime:
  nodes:
    trusted-targets:
      genb-test-node: 10.20.0.8
```

SSH 别名和地址必须由运维核验。空映射拒绝新增节点。本批代码不会执行 SSH、Docker 或健康探测。
