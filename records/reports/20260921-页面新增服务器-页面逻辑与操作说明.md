# 页面新增服务器：页面逻辑与操作说明

日期：2026-09-21。适用范围：GenB → 节点管理与监控 → 新增服务器。

原页面只登记运维已经配置好的 SSH 别名。新页面从服务器地址开始，生成连接公钥、核验服务器身份、安装节点程序，最后启用。节点名称可以用中文；节点编号和 SSH 别名由平台生成，不再要求用户填写。

首次仍需服务器所有者在目标服务器上授权平台公钥。平台不能在没有服务器授权的情况下直接接管服务器。页面提供授权命令，不需要向浏览器上传密码或私钥。

## 一、整体操作流程

```mermaid
flowchart LR
 A[填写服务器与资源信息] --> B[平台生成编号和公钥]
 B --> C[在目标服务器授权公钥]
 C --> D[读取并核对主机指纹]
 D --> E[检查连接和安装条件]
 E --> F[确认初始化内容]
 F --> G[安装及验证节点程序]
 G --> H[启用并加入节点目录]
 H --> I[部署项目并发布统一入口]
```

“节点已启用”说明专用连接、运行环境和监控采样检查通过。项目是否能够从统一入口进入，需要项目部署、健康检查、入口发布及授权访问的实际验证。

## 二、第一步：服务器信息

| 字段 | 用户填写什么 | 页面规则与提示 |
|---|---|---|
| 节点名称 | 例如“测试服务器”“上海 Python 节点” | 必填，最多 120 字；支持中文；后续可改。 |
| 服务器 IPv4 地址 | 47 控制服务器能连接的目标地址 | 必填；目前不支持域名和 IPv6；拒绝回环、组播、链路本地及云元数据地址。不是当前电脑的地址。 |
| SSH 端口 | 通常为 22 | 整数 1–65535；目标安全组和防火墙需要允许控制服务器访问。 |
| 初始化账号 | root、ubuntu、ec2-user 等实际存在的账号 | 必须是目标服务器已有 Linux 账号；需要 root 或免交互 sudo。不是平台登录用户名。 |
| 允许项目类型 | Python ZIP、Docker TAR，可多选 | 至少一种；默认仅 Python。选择 Docker 代表允许安装/启用 Docker；18 保持 Python-only。 |
| 部署端口池 | 默认 18000–18099 | 1024–65535，起点不超过终点，最多 1000 个。部署时仍检查端口占用。 |
| 单实例内存上限 | 默认 256 MiB | 最少 64 MiB；按服务器容量填写；它是单个项目允许的上限，不是立即预分配内存。 |
| 系统保留内存 | 默认 256 MiB | 最少 128 MiB；防止部署项目耗尽系统内存。 |

点击“下一步：生成连接公钥”时，页面先校验，后端再次校验。生成接入任务并不安装任何目标服务器软件。

重复处理：已登记的服务器显示“该服务器已在节点目录，请直接打开已有节点；不能重复初始化”。已有未完成接入任务的地址返回原任务，避免生成多套接入记录。

## 三、第二步：身份与连接

1. 页面显示本次任务的公钥和“查看公钥授权命令”。用户通过可信服务器控制台，以初始化账号执行命令，将公钥加入该账号的 `~/.ssh/authorized_keys`。
2. 点击“读取主机指纹”，平台读取目标 SSH 服务的 ED25519 指纹。读到指纹只说明 SSH 服务有响应，不代表登录授权已经通过。
3. 页面给出核对命令：`ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256`。在可信控制台执行，比较 SHA256 指纹。
4. 勾选“我已核对指纹，确认是目标服务器”，才允许点击“检查连接与安装条件”。未勾选时显示禁用原因。
5. 检查实际登录、管理员权限、Linux/systemd 和既有节点程序。服务器身份不一致时拒绝连接，不自动忽略检查。

页面会注明：授权命令必须在目标服务器执行，不要在自己的电脑或其他服务器执行。若服务器没有 ED25519 主机密钥，需要运维配置受支持的 SSH 主机密钥后再接入。

修改地址、账号或其他初始信息后，返回待核验状态，清除已确认指纹，重新核对连接。初始化开始后不能修改这些参数。

## 四、第三步：初始化

连接检查通过后，页面列出将要发生的修改：

- 检查 Linux/systemd、权限及既有节点；检测到原有节点程序或策略时停止，避免覆盖已有业务。
- 通过系统软件源准备 Python 3.9+、venv、ensurepip 和 sudo。自动安装适用于具备 apt 或 dnf 的系统；其他系统需预装依赖。
- 仅当选择 Docker 时安装或启用 Docker。
- 安装现有 GenB 节点执行程序、监控采样程序及端口/内存/项目类型策略。
- 创建 `genb-deploy` 受限运行账号，为日常部署登记专用连接。
- 检查运行环境、节点身份、监控协议和服务器时间。

用户勾选“确认在此服务器安装上述程序与策略”后，“开始初始化”可用。初始化在后台执行，页面每 3 秒查询状态。关闭页面后，可从“新增服务器 → 继续已有接入任务”恢复查看。

时间提示：软件源较慢时可能需要数分钟；远程安装等待上限 15 分钟。超时不表示服务器完全没有变化，应先核对实际安装结果。

安装并非事务：失败不会自动卸载共享系统依赖，也不会删除业务数据。成功后删除本次生成的初始化私钥，并移除目标服务器上本次授权的初始化公钥；专用运行连接继续保留。

## 五、第四步：检查并启用

页面显示 Python 版本、Docker 是否可用、可用内存和磁盘。“节点程序与监控检查通过”后才出现“启用并加入节点目录”。

点击启用会再次验证专用连接与监控，将节点登记到现有节点管理、监控和部署流程。重复点击不会重复生成节点记录。

启用后的实际操作：在项目部署页面选择新节点 → 上传节点允许的 Python ZIP / Docker TAR → 等待部署和健康检查 → 在运维页面发布统一入口 → 从项目入口进行账号授权和业务访问验证。

网关沿用动态路由机制。新增服务器和新增项目不需要逐个修改网关代码；服务器业务端口需要能被网关代理访问。页面不会自动开通云安全组、购买服务器或创建跨网络隧道。

## 六、异常提示及处理办法

| 情况 | 页面提示重点 | 下一步 |
|---|---|---|
| 名称为空 | 请填写节点名称，支持中文 | 填名称；不再填写节点标识。 |
| 地址非法 | 请填写有效服务器 IPv4 | 改真实目标地址。 |
| 账号格式错误 | 需小写字母或下划线开头，使用数字、下划线、短横线等允许字符 | 填实际 Linux 账号，不填中文备注。 |
| 资源参数错误 | 有效整数端口、实例内存至少 64 MiB、系统保留至少 128 MiB | 根据容量修正，不随意提高上限。 |
| 服务器已经登记 | 不能重复初始化 | 关闭向导，进入已有节点。18/47 使用原节点。 |
| 读取指纹失败 | 核对 IP、SSH 端口及控制服务器访问权限 | 检查安全组、防火墙、SSH 服务和 ED25519 主机密钥。 |
| SSH 登录失败或身份变化 | 核对指纹、授权账号、公钥权限和端口 | 修复授权或通过可信渠道确认主机变化，再核验。 |
| sudo 不可用 | 初始化账号需要 root 或免交互 sudo | 由服务器管理员配置权限。 |
| 系统不支持 | 需要 Linux、运行中的 systemd 和 flock | 不使用 Windows 或普通无 systemd 容器进行该初始化。 |
| 发现既有节点程序 | 已停止初始化，不覆盖业务目录 | 若是原节点，回节点目录；若是上次部分安装，先“核对安装结果”。 |
| Python 未就绪 | 需要 Python 3.9+、venv、ensurepip | 核查软件源或预装兼容版本。 |
| Docker 未就绪 | 检查软件源和 Docker 服务 | 修复环境；不需要容器部署时从初始配置选择仅 Python。已经开始的安装不支持直接改能力。 |
| 内存不足 | 不足以保留系统预算并运行最小实例 | 释放资源，先核对安装结果；未安装时重新检查安装条件。 |
| 安装失败 | 可能是软件源、磁盘、权限或兼容问题 | 先核对结果；确认没有节点程序后，才重新检查并安装。 |
| 进程中断或超时 | 服务器可能已完成部分安装，不能盲目重装 | “核对安装结果”；仍未完成则运维处理具体原因。 |
| 专用连接或监控验证失败 | 尚不能启用；检查程序、genb-deploy 授权及系统时钟 | 修复后再次核对安装结果。 |
| 任务正在执行 | 等待并刷新进度 | 不重复点初始化。 |
| 页面服务未启用或控制端程序缺失 | 联系平台管理员完成控制端安装 | 属于平台配置问题，不要求用户更换节点名称。 |

## 七、刷新、恢复与状态

| 页面状态 | 允许动作 |
|---|---|
| 待授权 / 待核对指纹 / 检查未通过 | 修改信息、读取指纹、授权和检查连接。 |
| 待初始化 | 修改信息并重新核验，或确认初始化。 |
| 初始化中 | 查询进度、关闭后恢复；不能重复初始化。 |
| 初始化未完成 | 核对安装结果，或重新检查安装条件；不直接覆盖重装。 |
| 待启用 | 启用并加入节点目录。 |
| 已启用 | 返回节点目录管理。 |

进程中断检测在查询任务时执行；进入安装状态超过两分钟且执行锁已释放，才标记中断。页面接入记录展示最近 50 个任务。

## 八、运维需了解的实现位置

- 页面：`NodeOnboarding.vue`；主入口：`NodesPage.vue`；字段验证及错误说明：`onboardingModel.js`。
- 后端 API：`RuntimeNodeOnboardingController`；仅管理员 / 超级管理员可操作。
- 控制端执行：`node_onboarding.py`；目标初始化：`onboard_install.sh`，复用现有节点程序和安装脚本。
- 持久目录默认 `/var/lib/genb-onboarding`；目录 0700、状态及密钥文件 0600。必须纳入受保护备份；丢失运行私钥会影响托管节点连接。
- `RemoteNodeClient` 优先使用平台生成的节点连接配置；旧节点继续使用原有配置。
- 当前支持单控制服务器。多控制服务器共享接入状态、密钥与分布式锁不在本次交付范围。

## 九、验证边界

页面流程、输入校验、身份确认门槛、已有节点保护、状态恢复和构建检查分别验证。没有可初始化的新服务器时，不能把模拟执行测试写成“真实新服务器完整部署成功”。18 和 47 已经是运行中的节点，不通过重装它们来替代新增服务器验收。真实新主机仍需完成接入、部署样例和统一入口访问验收。
