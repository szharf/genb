# 统一数据面网关 M4 完成报告

- 日期：2026-08-13
- 范围：本地缓存、失效、审计与恢复纵向切片
结论：Gate E通过

## 1. 背景

M3已经把核心能力调用收敛到统一网关，但运行时仍缺少生产语义所需的配置缓存、撤权时限、审计背压和依赖故障恢复。M4只完成这些本地能力，不进入服务器检查或生产部署。

## 2. 目标

保证路由与能力绑定不出现混合版本；撤权在5秒内失败关闭；控制面长时间不可用时旧配置不超过15分钟；缓存、审计和重试均有明确上限；Redis或GenB恢复后能够安全收敛。

## 3. 修改范围

- 数据面新增完整快照运行时、Redis LKG、2秒轮询和机器身份主动失效。
- Gateway Session新增5秒L1、Redis主体索引和撤权拒绝墓碑。
- Actor Token新增隔离键缓存与精确失效。
- 审计新增有界Redis Stream和最大100条批量提交。
- GenB在配置发布、用户撤权和角色撤权事务提交后通知网关。
- 上游只对幂等READ补偿重试一次。

没有修改服务器、生产Nginx、生产Redis、生产数据库或运行容器。

## 4. 实现结果

快照只在闭合信封、版本和全部路由/绑定均可编译时整体替换；路由与能力表始终来自同一版本。高风险读取在失联超过5秒后返回`CONFIGURATION_UNAVAILABLE`，低风险LKG硬上限为15分钟。主动失效仅接受配置、能力、精确会话、用户智能体和智能体五种范围。

撤权首先清除L1并登记拒绝墓碑，再写Redis；因此Redis短暂失败后，旧记录恢复也不能重新授权。Actor Token的缓存键包含tenant/user/agent/session/capability/bindingVersion，最长5分钟并预留安全边界。审计Stream达到容量后明确背压，提交失败不删除且不无限重试。

## 7. 风险与边界

- 本地拒绝墓碑保护当前网关进程；跨进程长期可靠通知仍需要生产部署阶段的实例拓扑和可靠投递设计确认。
- 本地Nginx真实回环用例本轮未启动，因此按环境条件跳过；M2已有真实`nginx -t`和回环证据，M5将统一重跑完整本地栈。
- 本报告不证明生产高可用、容量、网络策略或服务器资源满足上线条件。
- 当前工作树包含用户和前序里程碑修改，未执行提交、推送或破坏性Git操作。
