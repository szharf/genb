## 任务：修复 test_user 的 GenC 普通用户映射并接通 GenO 远程用户库

### 1. 背景

管理员在统一权限管理中把 `test_user` 配置为 GenC 普通用户时，保存接口返回 500。与此同时，GenO 用户目录一直只有 `admin`，与同事已经新增多名用户的情况不一致。

如果不处理，普通用户无法正常完成 GenC 授权，GenO 管理页面也无法选择真实服务器上的用户。

### 2. 目标

让 `test_user` 能保存为 GenC 普通用户并正常解锁入口；让本地 GenO 服务读取真实远程用户数据库；让最新 GenB JAR 替换旧运行版本。

测试结果：

- 根因：保存角色后，管理查询调用权限解析器；用户尚无入口授权时解析器抛出安全异常。代码虽然捕获异常，但 Spring 已把外层事务标记为回滚，提交时返回 `UnexpectedRollbackException`。
- 修复：没有有效入口授权时直接返回空的最终权限，不调用拒绝型解析器；安全异常不再污染管理保存事务；新用户第一次选择 GenC 角色时默认打开直接授权，继承授权用户保持原逻辑。
- 后端完整测试 74/74 通过；管理端表单测试 7/7 通过；Vite 生产构建成功。
- 远程 GenB 上 `test_user` 保存返回 200：映射有效、直接授权有效、角色为 `USER`、权限为 `journey.editor` 和 `journey.home`、入口已解锁。
- 8581 最新 JAR PID 为 34088，连接远程 GenB PostgreSQL；健康接口 200。
- GenO 数据库为 PostgreSQL 16，数据库 `ontoprompt`、schema `public`；只读事务显示 `transaction_read_only=on`。
- `public.users` 实际 17 行，全部为启用用户；Genesis 服务端用户目录接口也返回 17 人。
