# 核心组件本地403与菜单层级修复报告

## 1. 背景

用户通过本地 `localhost:9100` 客户端进入管理端后，核心组件目录请求返回403，页面显示加载失败；同时左侧导航没有把“智能体列表”和“核心组件”归入“智能体中心”。第一轮错误验证了9000和公网入口，本报告已按用户提供的实际地址纠正。

## 2. 目标

修复本地9100同源登录链中的管理端鉴权，修正菜单信息架构，并用真实浏览器证明原403已消失；本任务不部署。

## 3. 范围

本次完成：9100真实浏览器复现、统一管理端Token读取、Token回归测试、菜单父子结构、智能体列表标题、中英文文案、双语构建和本地9100浏览器验收。

本次不做：不部署、不修改后端、数据库或Nginx。

## 7. 根因与预防

根因是客户端与管理端各自硬编码不同Token键，且API模块重复实现请求拦截器。统一Token解析函数让键选择成为单一事实来源；回归测试明确覆盖“只存在客户端Token”的真实入口条件。

## 8. 纠正说明

上一版报告把公网目录404误判为用户的加载失败根因，并错误提出部署。用户实际报告的是本地9100目录403。该结论已撤回并替换，公网状态不属于本任务。
