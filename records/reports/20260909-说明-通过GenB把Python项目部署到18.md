# 通过 GenB 把 Python 项目部署到 18

本次保留两种启动方式。47 可以运行 Python 项目或 Docker 镜像；18 只运行 Python 项目，不安装 Docker。后续新增智能体通过平台登记和发布，不需要逐个修改 Nginx 或网关代码。

## 操作位置

登录统一门户，进入 GenB 管理端，在智能体的部署页面使用新的“多节点”部署区域。节点管理中可以看到：

| 节点 | 允许 Python | 允许 Docker | 项目运行环境 |
|---|---|---|---|
| 18 · Python 专用 | 是 | 否 | Python 3.11.15、venv、systemd |
| 47 · Python / Docker | 是 | 是 | Python 3.11.13、venv、systemd、既有 Docker |

“允许”是管理员的配置，“环境可用”是服务器的实际检查结果。两者都满足才能部署。检查超过五分钟时，请重新点击“检查环境”。选择 Docker 类型时，18 不会出现在可选节点中；绕过页面直接提交也会被后端拒绝。

## 准备 FIBO 项目

本次确认的路径是 `D:\code\opencode\fibo_refactor`。本轮不修改这个仓库，也不代替你部署真实 FIBO。

把项目代码打成 ZIP，让 `server.py`、`requirements.txt`、`config.py` 和业务目录直接位于 ZIP 根目录。排除 `.git`、本机虚拟环境、缓存、`node_modules` 和无关历史产物。不要把整个仓库再套一层 `fibo_refactor/` 目录后压缩。

该项目的 `server.py` 能接收启动端口参数，前端也已经根据当前路径构造 API 地址，具备 `/agents/{智能体ID}/` 的基本适配。

项目根目录可选放置 `genb.env`，由运行程序读取为环境变量。18 的首次轻量测试可以参考：

```dotenv
ALAYA_API_URL=http://47.116.69.17:8002/api/v1/llm/chat
ALAYA_PROVIDER=minimax
ALAYA_THINK=false
LLM_MODEL=MiniMax-M2.7-highspeed
USE_FUSEKI=false
USE_PELLET=false
LEDGER_DB_TYPE=sqlite
LEDGER_SQLITE_PATH=audit_ledger.db
```

这是轻量测试配置：关闭 Fuseki 和依赖 Java 的 Pellet，会改变相关本体存储和推理能力，不能据此认定完整业务能力已验收。如果测试必须使用这些能力，应连接已经准备好的外部服务，并明确 Java 及资源需求。不要沿用部署示例中的 `127.0.0.1:8002` 或 `/app/fibo_refactor/shared/`：它们对应旧环境，在 18 的新实例中含义不同。

模型服务是否允许 18 访问、模型是否可用、业务数据与权限是否正确，属于真实 FIBO 的业务验收。FIBO requirements 未锁定版本，包含 OWL、LangChain 等依赖，安装可能需要额外编译环境；安装日志会给出实际结果。本轮平台测试项目不能代替这些业务依赖的完整验证。

## 上传、启动和访问

1. 创建或打开目标智能体，进入部署页面。
2. 项目类型选 **Python ZIP**，目标节点选 **18 · Python 专用**。
3. 上传 ZIP，启动方式选 **Python script**，入口填写 `server.py`。
4. 节点端口选一个未占用的 `18000—18099` 端口，首次建议 `18001`。18 内存上限最高 256 MiB；FIBO 首测可设 256 MiB，是否足够需看实际运行结果。
5. 点击上传并部署，等待材料分发、依赖安装、进程启动和 HTTP 检查。页面可查看任务、实例和日志。部署操作本身不会立即对外发布。
6. 实例健康后点击发布，等待状态变为 **APPLIED / 网关已生效**，再点击统一入口。
7. 入口形式为 `http://18.167.156.11/agents/{智能体ID}/`。当前试点使用 HTTP 的 18 IP；HTTPS 正式域名需要在确定域名与证书后另行配置。其他已有网站域名上的新智能体路径会转到该统一入口。

没有登录时先进入统一登录。发布尚未生效时，客户端不会退回裸 IP 和端口打开项目。普通智能体的网关发布不依赖核心组件绑定。

## 停止、失败与限制

- 先撤下路由，等网关确认，再停止实例。避免访问入口还在接收请求时直接停止服务。
- Python 停止后也取消开机启动；重新启动会恢复开机启动。项目代码和任务记录保留。
- 任务结果未知时平台先核对远端状态，不盲目重建。失败记录和端口会保留用于排查；当前重试使用新任务和未占用端口。
- 不提供多副本、自动迁移、滚动发布或自动清理。18 是低资源试点节点，建议一次只运行一个业务实例。
- 项目被分配独立运行用户与目录，但应用自己的业务数据隔离仍需由应用实现。不能因为经过统一登录，就把共享 SQLite 自动视为用户数据隔离。
