- 日期：2026-09-15
- 状态：开发与本地验证已完成；整体计划执行中；本轮未生产发布。
- 计划：[多节点管理、监控与部署访问完善](../plans/20260915-PLAN-多节点管理监控与部署访问完善.md)，版本 1.2。

## 1. 本轮结果

管理员新增独立“节点管理”入口，可以查看服务器支持的项目类型、资源快照和趋势、项目与实例数量，以及接入检查结果。节点支持暂停新部署、排空和受依赖保护的退役。18 继续只运行 Python 项目，无需安装 Docker 或重型监控服务。

这些是当前源码实现和隔离测试结果，线上仍运行原版本。尚未完成的第三节点全流程、旧项目迁移和真实业务验收继续保留为必须项。

## 2. 实现范围

| 功能 | 本轮实现 | 边界 |
|---|---|---|
| 节点目录 | 独立列表、分页筛选、登记、编辑、能力开关、详情 | 登记前由运维准备可信 SSH 目标；不能填写任意 IP 自动安装 |
| 生命周期 | ACTIVE / PAUSED / DRAINING / RETIRED；版本检查、幂等键和审计 | 暂停/排空阻止新部署和新入口发布，不停止已有业务；退役检查实例、任务和网关依赖 |
| 资源监控 | 固定 metrics v1 动作；CPU、内存、部署目录磁盘；30 秒采样、2 并发、5 秒超时 | 首次 CPU 无差值则显示未知；90 秒过期不冒充实时；旧执行器明确不支持 |
| 历史与容量 | 原始样本 24 小时、5 分钟聚合 7 天；定期清理 | 查询最多返回 1,000 个均匀抽样点；无数据间隔不连接成连续测量 |
| 数量统计 | 区分项目、实例、运行、停止、异常和未知；旧模式部署单列 | 仅统计 GenB 管理记录；不是服务器全部进程；旧部署记录数不等于运行实例数 |
| 站内告警 | CPU/内存默认 85%、磁盘 90%；持续 5 分钟打开，恢复持续 2 分钟关闭；采样不可用事件 | 不发送邮件、短信；不可用不等于已经证明物理服务器宕机 |
| 接入检查 | 固定环境/指标/代理配置检查、可重入任务、检查历史 | 管理连通不等于业务连通；没有业务样例时保持 NEEDS_SAMPLE，不显示全部通过 |
| 部署诊断 | 预检、材料传输、远程结果未知、健康检查等失败码 | 保留安全原因，不把未知远程结果误判为明确失败；不自动跨节点构建复杂依赖 |
| 项目入口 | 节点实例清单可进入已有部署/运维界面，访问已发布项目入口 | 入口属于项目当前发布版本，不承诺打开清单中任意历史实例 |

实现位置：子仓库 `gen-b-backend/node-runtime/`、后端 `RuntimeNode*` 服务/实体/仓库及 `RuntimeMetricMath`、节点控制器、原部署与网关保护、控制台 `src/components/nodes/` 和路由。接口文档为 `contracts/genb-runtime-nodes.openapi.json` 0.4，采样合同为 `contracts/genb-node-metrics.schema.json`。

## 4. 服务器只读实测与数据库演练

- 18：连续 11 次轻量采样跨约 300 秒；采集路径峰值内存约 11.3 MiB，单次 CPU 时间约 0.0064 秒。[样本](assets/20260915-节点管理监控/metrics18.jsonl)
- 18：完整候选节点程序只读 metrics 路径在内存加载执行，峰值约 16.4 MiB，单次 CPU 时间约 0.024 秒。未替换已安装节点程序。[完整路径结果](assets/20260915-节点管理监控/full-metrics18.txt)
- 47：单次只读采样成功，采集路径峰值约 12.3 MiB；不是完整节点程序压测。[结果](assets/20260915-节点管理监控/metrics47.txt)
- PostgreSQL：事务内创建独立验证 schema、复制基础表结构并执行本轮三个迁移；1,000 条样本连同索引占 368,640 bytes（360 KiB），保留期删除 880 条后剩 120 条；最终 ROLLBACK，验证 schema 剩余数为 0。[演练结果](assets/20260915-节点管理监控/postgres-migration-check.txt)

这些结果支持轻量方案可行性，不能据此声称长期容量或生产运行影响已全部验证。生产业务表、本轮监控开关、现有业务实例及已安装程序均未在本轮升级。

## 5. 兼容与旧项目盘点

既有节点列表接口仍返回数组，新分页总览使用独立接口；监控开关默认关闭，旧执行器可继续原部署流程。18 本地策略仍限制 Python-only，47 可支持 Python 与 Docker。

只读盘点得到 11 个旧模式项目。Loop Engineering、SDD设计智能体当前均登记为 STOPPED 且各 1 条旧部署记录，可作为进一步评估候选；停止状态不代表数据不重要或已获得迁移授权。已询问用户选择，当前没有迁移任何旧项目。联合推理实例基线为 HEALTHY，入口数据库登记 PUBLISHED；本轮没有以该登记替代实时网关 ACK 或完整业务验证。
