# 智能体绑定、统一退出、测试凭证与短期记忆聊天智能体实施报告

> 日期：2026-07-30
> 本地唯一入口：`http://localhost:9100`

## 1. 交付结果

本次五项要求均已完成。核心组件绑定表展示智能体名称和ID；管理端与客户端退出统一回到`/portal/login`；退出后直接访问受保护管理路由会在渲染前被拦截；智能体绑定测试按智能体保存、自动回填并在调用后保留凭证；`standalone-memory-test-agent`具备客户端聊天页面并真实完成短期记忆的读取和提交。

## 2. 页面与认证行为

- 绑定表优先使用智能体目录中的名称，同时保留稳定ID；目录缺失时安全回退为ID。
- 两端退出都会清理`token`、`genb-client-token`以及关联用户缓存，然后使用`location.replace('/portal/login')`，浏览器后退也不会回到已登录页。
- GenB Console全局路由守卫在受保护页面渲染前检查登录Token；没有Token时取消本次导航并进入统一门户。
- 客户端API收到401/403时执行相同清理和跳转规则。

## 3. 测试凭证规则

服务端继续只保存不可逆哈希，不新增明文凭证字段。管理员在测试台生成、轮换或手动填写凭证后，页面按`agentId`保存到当前浏览器本地存储；选择同一智能体时自动回填，真实调用和页面刷新均不清空，吊销时同步删除。

历史凭证明文无法从后端恢复。因此浏览器首次使用且没有本地副本时，需要轮换一次或手动填写。该限制来自现有安全模型，不是页面加载失败。凭证不会下发给客户端聊天页，也没有写入数据库、源码、文档或Git。

## 4. 测试智能体架构

`standalone-memory-test-agent`是独立HTTP聊天服务，监听`127.0.0.1:18711`。聊天页只携带当前用户JWT；智能体进程从环境变量读取自身长期服务凭证，随后：

1. 使用用户JWT和智能体凭证向GenB申请`SHORT_TERM_MEMORY`组件会话。
2. 从GenB动态绑定响应取得Implementation地址和Actor Token。
3. 调用`context:prepare`读取同一`agentId + userId + taskId`下的上下文。
4. 生成可重复验证的测试回答。
5. 调用`turns:commit`提交用户消息和回答。

未绑定、绑定停用、凭证错误或用户Token失效都会在GenB门禁处失败；聊天服务不绕过绑定验证。

启动脚本为`scripts/start_standalone_memory_test_agent.ps1`。默认由GenB轮换并注入新凭证；已有Secret时可设置`SERVICE_CREDENTIAL`并使用`-CredentialFromEnvironment`保持同一长期凭证。日志不输出服务凭证或Actor Token。

本次没有新增数据库表或物理外键，没有变更9100/9000入口结构，也没有部署公网环境。
