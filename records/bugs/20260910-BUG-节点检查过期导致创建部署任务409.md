# 节点检查过期导致创建部署任务 409

日期：2026-09-10。

## 现场证据

用户报告 02:55:09 UTC 的 `POST /api/v1/runtime-deployments` 返回 409 Conflict，没有具体原因。

数据库只读核验：用户 Python 材料已在 02:55:02 UTC 上传成功；没有创建对应部署任务或实例。node18/node47 均 READY 且能力许可正常，但 observed_at 分别停留在前一天 08:04:39/44 UTC。服务要求检查记录不超过 300 秒，直接拒绝过期节点。Spring 默认错误响应未包含 ResponseStatusException 的业务原因，前端又保留 Axios 通用 message，形成不明确的 409。

## 改动

- 创建任务或启动实例时，先校验管理员设置的节点启用和项目类型许可；检查记录过期/缺失时自动调用节点 probe，再校验实际能力。
- 保留 300 秒时效约束；不能通过放宽过期限制冒充节点健康。自动检查不越过管理员的类型禁用设置。
- SSH 检查失败返回 503 和明确的连接检查提示，不泄露底层异常；不创建任务。
- 仅为 RuntimeDeploymentController/RuntimeNodeController 添加业务异常响应处理，返回 HTTP 状态和 Result.message。
- 管理端 Axios 保留原 response/status，并将可读提示写回 error.message，让页面和提示框一致。
- 幂等请求仍先返回已有任务，不重复检查或部署。

## 验证

- 修复前新增三项回归全部失败；修复后后端 205 项，0 失败、0 错误、1 跳过。
- 覆盖昨日检查自动刷新后入队、重复请求仅检查一次、连接失败不创建任务、管理员禁止类型时不调用远端。
- 前端 HTTP 409/503/401 三种错误信息和元数据行为检查通过；中英文生产构建通过。
