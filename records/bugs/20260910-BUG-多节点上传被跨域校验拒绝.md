# 多节点上传被跨域校验拒绝

日期：2026-09-10。状态：已修复并部署。

## 现象与原因

用户从 18 的管理端上传项目，`/genb/api/v1/runtime-deployments/artifacts` 返回 HTTP 403、正文 `Invalid CORS request`。

新上传精确 location 为适配上游入口，将 Host 固定为 47.116.69.17；浏览器保留真实 Origin `http://18.167.156.11`，触发后端跨域校验。SecurityConfig 仍允许已退役的 16 地址，未允许当前 18；WebConfig 的第二层 MVC 白名单也仅允许两个 localhost 地址。只修任意一层都不足以保证实际上传通过。

## 修复

- SecurityConfig 和 WebConfig 共用当前入口白名单，允许 18、alaya.to、genesis-engine.ai 的 HTTP/HTTPS 来源；保留既有本地开发来源，撤销全局旧 16 来源。
- 对齐两层允许的方法，保留管理员权限约束及凭据处理。
- 未修改 Nginx、5 GiB 上传限制、项目文件、节点配置或数据库。配置允许 HTTPS 来源不代表已新增 HTTPS 证书。

## 验证

- 修复前：公网 OPTIONS 和独立浏览器 FormData POST 均复现原 403 文本；新增测试 10 项中 9 项失败。
- 修复后：后端完整测试 202 项，0 失败、0 错误、1 跳过；新增 10 项全部通过。包含管理员 multipart 穿过两层校验进入业务检查（不存在智能体返回 404）、普通用户 403、当前入口预检通过、陌生及退役来源被拒绝。
- 生产临时端口 18581 先验证健康和来源策略，再切换正式 8581。
- 公网中英文两个上传路径分别验证当前来源 OPTIONS 200、陌生和旧 16 来源 403。
- 独立浏览器实际 multipart 请求由原跨域错误变为正常未登录 Forbidden JSON，携带正确 Access-Control-Allow-Origin；权限未绕过。
- 四套 GenB 前端、GenO、FIBO 页面及 FIBO status、GenB health 均 HTTP 200。

本次浏览器工具仅连接独立浏览器，未取得用户日常 Chrome 的登录态。没有宣称完成用户项目的生产上传或 FIBO 部署；用户刷新管理端后重试原上传。
