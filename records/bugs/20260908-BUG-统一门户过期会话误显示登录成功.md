# 统一门户过期会话误显示登录成功

- 日期：2026-09-08
- 状态：本地修复与回归完成，未提交、未部署。
- 现象：用户前一天登录未退出，隔天打开 /portal/login，页面显示登录成功、会话有效，但账号为空，平台全部锁定。
- 计划：`records/plans/20260908-PLAN-统一登录过期会话恢复修复.md`。

## 证据与结论边界

测试挂载真实 PortalLoginView，使用真实 useGenesisPortal 和 api/genesis.ts 拦截器，只替换 Axios 传输层及无关背景/平台卡片展示。模拟本地存有上一日凭据，/auth/me 返回 HTTP 200、业务 code=401 且无 data，平台响应延迟，可复现截图全部关键文案：空账号、普通用户、0 个平台、安全有效、登录成功。

后端 GenesisPortalController.me 与 myPlatforms 确实可以以普通 Result 返回业务 401，而非 HTTP 401。线上当时是否省略 data、平台请求是否延迟，以及实际令牌失效时间尚未捕获，不将本地响应组合直接当作已证实的生产网络记录。

已证实的本地问题：

1. Axios 成功拦截器没有校验业务 code，错误对象可能作为用户数据返回。
2. 用户数据未进行必要形状校验，空对象也被当作有效身份。
3. 恢复时先写 user，再等待平台，提前显示登录成功及零平台。

这不证明用户实际授权被删除；本轮没有查询或修改数据库授权。

## 修复

- api/genesis.ts：解包前拒绝非 200 业务码；校验恢复用户的非空账号、角色和平台数组；校验平台列表为数组。
- useGenesisPortal.ts：恢复期间标记加载中，身份和平台准备完毕后同时提交；失败清理本地凭据并在登录表单显示错误。
- 恢复请求记录会话代次，退出、重新登录及页面卸载使旧请求失效，防止迟到响应写入用户或清除新会话。
- 保留正常零授权用户与首次强制改密流程；未改登录时长、数据库、后端代码或页面视觉。
