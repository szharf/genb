# Genesis 统一登录 12 秒超时与 GenB 后端磁盘满

日期：2026-08-10

## 现象

- `http://16.162.33.130/portal/login` 页面可正常加载。
- 提交统一登录后前端显示 `timeout of 12000ms exceeded`。
- Nginx 访问日志中的登录请求为 `499`，表示浏览器等待 12 秒后主动断开。

## 最小复现

```text
GET http://16.162.33.130/genb/api/actuator/health
```

故障时 TCP 可连接，但 15 秒内没有响应；从前端服务器直接访问 `47.116.69.17:8581` 同样超时。

## 根因

- 后端服务器根分区达到 `100%`，可用空间为 `0`。
- GenB Java 进程仍监听 `8581`，但本机健康接口也连续 10 秒无响应。
- 同一后端服务器上的 GenC 服务仍正常，因此故障集中于 GenB 进程，不是 Nginx、门户静态页或整台服务器宕机。

## 处理

- 将 systemd 归档日志收敛到 512MB，释放约 2.2GB。
- 执行 `dnf clean all`，删除 56 个软件包缓存文件。
- 使用 `/app/gen-b-console/stop.sh` 精确停止旧 PID；旧进程优雅停止超时后由脚本按 PID 强制结束。
- 使用 `/app/gen-b-console/start.sh` 启动新进程。
- 删除 3 个无容器引用的 Docker 悬空镜像；镜像层均被其他镜像共享，实际释放空间为 0B。

未修改数据库、Nginx 配置、JAR、Docker 容器、Docker 卷或业务文件。

## 验证

- 新进程启动约 12 秒后，本机健康接口返回 `{"status":"UP"}`。
- 浏览器真实统一登录请求返回 `HTTP 200`；此前三次故障请求均为 `499`。
- 三轮公网回归全部通过：GenB `200`（约 0.60–0.64 秒）、GenC `200`（约 0.38–0.41 秒）、GenO API `200`（约 0.27 秒）。

## 剩余风险

- 根分区仍为 `98%`，可用约 2.6GB。
- `/var/lib/docker` 约 65GB；GenB 历史 JAR 备份约 1.5GB；17 个未挂载 Docker 卷未清理。
- 后续必须单独盘点镜像、卷、构建产物和历史备份归属，在保留必要回滚点后将磁盘降到安全水位。
