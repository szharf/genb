# 核心组件公网加载失败与菜单层级错误

## 现象

1. 管理端进入“核心组件”页面后显示“核心组件目录加载失败”。
2. “智能体中心”和“核心组件”被实现为两个并列一级菜单；正确结构应为“智能体中心”父菜单，下设“智能体列表”和“核心组件”。

## 复现步骤

1. 使用有管理端权限的账号进入中文管理端。
2. 点击“核心组件”。
3. 公网页面请求 `GET /genb/api/v1/core-components`，收到 HTTP 404。
4. 查看左侧导航，可见“智能体中心”和“核心组件”处于同一级。

## 原因

- 加载失败不是 Vue 页面逻辑或数据库数据问题。2026-07-23 的分层探针结果为：本地 8581 后端直连返回 HTTP 200/14 条，本地 Vite 代理返回 HTTP 200/14 条，公网同一目录接口返回 HTTP 404；公网 Nginx 代理指向的后端仍是未包含核心组件接口的旧版本，属于前后端部署版本错配。
- 菜单问题来自 `MainLayout.vue` 将两个路由直接声明为并列 `el-menu-item`，并且原智能体页面仍使用“智能体中心”作为自身标题。
- 英文管理端与中文管理端共用 `/genb/api/`；`/genb-en/` 只承载英文静态资源，不需要也不应新增独立英文后端。

## 修复方案

- 新增稳定导航模型，固定“智能体中心 → 智能体列表、核心组件”父子关系，并增加结构回归测试。
- 使用 `el-sub-menu` 默认展开父菜单，补齐子菜单样式及中英文文案。
- 将原智能体页面的路由标题和面包屑改为“智能体列表”/“Agent List”。
- 公网加载恢复需要把当前 GenB 后端部署到公网 Nginx 实际代理的后端实例；部署前必须备份 JAR、核对运行环境并完成健康、登录、目录接口和原有接口回归。本次未在缺少新的生产部署授权时替换服务器文件。

## 验证结果

- 导航结构测试通过。
- 核心组件目录与详情模型测试通过。
- 管理端中文、英文生产构建通过。
- 本地真实 Chrome 验收通过：父菜单唯一且默认展开，两个子菜单各一个；进入智能体列表后面包屑正确；进入核心组件后目录接口 HTTP 200、返回 14 条，页面不显示加载失败。
- 公网目录接口仍为 HTTP 404，等待后端部署，不标记为已恢复。

## 是否需要回归测试

需要。每次部署至少验证中文和英文静态入口、共享 `/genb/api/`、管理员登录、核心组件 14 条目录、原智能体列表、Genesis 统一登录与权限页面。
